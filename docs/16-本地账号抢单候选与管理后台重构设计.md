# 本地账号、抢单候选与管理后台重构：需求和设计

## 1. 本批目标

1. 共享队列有 5 名可抢单人员时，提交工单后详情显示这 5 人；任一人员抢单成功后，只显示实际受理人。候选快照继续留作服务端审计，但不在领取后继续显示为“当前候选”。
2. 系统和工单目录管理改为标准管理后台：筛选栏、分页表格、状态列、操作列、弹窗表单和详情抽屉。操作主线为系统列表 → 系统下工单服务列表 → 表单/流程配置，减少卡片和平铺表单。
3. 当前阶段不依赖 IAM。支持本地账号密码登录、会话、退出、账号停用、密码重置、角色和负责系统配置。
4. 普通用户登录后可提单、查看自己的工单和已发布知识；运维人员只能查看、抢单和处理其负责系统范围内的工单；平台管理员管理账号和系统范围。
5. 未来外部系统的客户端模式使用独立的机器身份和 OAuth 2.0 Client Credentials，不复用人的密码、浏览器会话或 CSRF 机制，本批只预留领域边界和配置契约，不签发自制长期 Token。

## 2. 调研与 UI 结论

项目已使用 Vue 3 + Element Plus，无需引入第二套后台框架，也没有必要安装来源不明的 UI skill。采用项目内可复用的“管理表格模式”：查询表单 + Table + Pagination + Dialog/Drawer。Element Plus 官方 Table 支持排序、过滤、单行选择和自定义操作列；Dialog 官方示例直接支持表格/表单内容；Form 提供统一校验容器：

- [Element Plus Table](https://element-plus.org/en-US/component/table)
- [Element Plus Dialog](https://element-plus.org/en-US/component/dialog.html)
- [Element Plus Form](https://element-plus.org/en-US/component/form)

页面规范：默认一屏只显示一个主列表；新增/编辑用 Dialog，详情和子资源用 Drawer；危险动作二次确认；状态变化代替物理删除；表格保留加载、错误、空态、分页和并发版本提示；操作列固定在右侧，最多 3 个高频动作，其余放“更多”。

## 3. 本地账号和认证模型

### 3.1 数据模型

- `platform_local_account`：稳定账号 ID、规范化登录名、`{bcrypt}` 密码哈希、启用状态、失败次数、锁定时间、密码更新时间、并发版本和审计字段。
- 人员显示名、组织和系统授权继续使用现有稳定人员 ID 及投影/后台授权表，来源标记为 `LOCAL_ACCOUNT`；这是兼容当前授权代码的内部目录投影，不代表已经接入 IAM。
- 登录名大小写规范化并唯一。密码不进入日志、审计属性、响应、消息或前端持久化。
- 平台管理员可创建账号、修改显示信息、启停账号、重置密码、配置角色和 `SERVICE_SYSTEM` 数据范围；删除语义为停用，不物理删除历史主体。

### 3.2 安全规则

- Spring Security 浏览器会话；登录成功更换 Session ID，Cookie 为 HttpOnly、SameSite=Lax，生产 HTTPS 下 Secure。
- 使用 Spring Security `DelegatingPasswordEncoder` 的 bcrypt 自适应哈希，不使用明文、可逆加密或 NoOp。官方建议使用自适应单向函数并把校验成本调到约 1 秒以内：[Spring Security Password Storage](https://docs.spring.io/spring-security/reference/features/authentication/password-storage.html)。
- 密码长度 12–128；账号/密码错误统一提示；连续 5 次失败锁定 15 分钟；成功登录清零失败计数；管理员重置密码写审计并使既有会话失效。
- `GET /api/v1/csrf` 和登录入口允许未认证访问；登录 POST 仍校验 CSRF。退出 POST 校验 CSRF并使 Session 失效。
- 首个管理员由仓库外环境变量一次性引导创建；已有账号后忽略引导密码。local-dev 可提供明确标识的测试账号，生产不包含默认密码。

### 3.3 接口

- `POST /api/v1/auth/login`：登录名、密码；成功返回当前用户投影并建立会话。
- `POST /api/v1/auth/logout`：注销并清理会话。
- `GET /api/v1/admin/local-accounts`：分页、登录名/显示名搜索、状态/角色/系统筛选。
- `POST /api/v1/admin/local-accounts`：创建账号及初始角色/系统范围。
- `PUT /api/v1/admin/local-accounts/{id}`：乐观锁修改资料、启用状态、角色和系统范围。
- `POST /api/v1/admin/local-accounts/{id}/password-reset`：管理员重置密码并使会话版本失效。
- `DELETE /api/v1/admin/local-accounts/{id}`：软停用；存在当前任务时仍保留历史快照并禁止新登录/抢单。

## 4. 角色和系统范围

| 角色 | 默认能力 |
| --- | --- |
| REQUESTER | 创建工单、读取自己发起的工单、查看已发布知识 |
| FIRST_LINE_SUPPORT / SECOND_LINE_SUPPORT | 在 `SERVICE_SYSTEM` 范围内查看、抢单、处理和内部沟通 |
| SERVICE_MANAGER | 管理负责系统的目录、队列和工单，不能越过系统范围 |
| PLATFORM_ADMIN | 管理本地账号、平台配置和全部授权范围 |
| AUDITOR | 只读授权范围内历史与审计，不可抢单或下载敏感附件 |

现有 `TicketAccessScopeResolver` 已支持 `DATA_SCOPE_SERVICE_SYSTEM:<systemCode>`。本地账号的负责系统写入现有后台数据范围，候选解析、工单列表、详情读取和动作提交都复用同一服务端对象权限，不由前端菜单决定。

## 5. 抢单候选读模型

现有 `ticket_workflow_queue_routing_snapshot` 已在任务创建时冻结候选人员 ID。本批不重新计算并冒充当时快照：

- 活动任务为共享队列、未领取且主办人为空：`WorkflowOverview` 返回 `acceptanceCandidates`，包含快照中的人员安全展示信息和数量。
- 当前领取动作仍重新校验账号启用、角色、队列成员、系统范围和任务版本；两个用户并发抢单只允许一个 CAS 成功。
- 领取成功后：`acceptanceCandidates=[]`，`primaryAssignee` 只返回领取人；旧候选集合仅保存在追加式路由快照/审计中。
- 申请人和有工单读取权限的运维人员可看到候选显示名/组织；不返回手机号、邮箱、密码状态、角色全集或其他系统范围。
- 非共享队列的系统随机分派直接显示已分派人，不显示“可抢单人员”。

前端在处理摘要和流程页显示“可抢单人员（5）”头像/姓名；领取后替换成“当前处理人：我/姓名”。

## 6. 系统与目录 CRUD 页面

### 6.1 系统列表

列：系统编码、系统名称、所属组织、负责人、状态、工单服务数、更新时间、版本、操作。

筛选：名称/编码、状态、组织、负责人。操作：查看、编辑、上架/下架、管理服务、表单与流程；新增系统在 Dialog 完成。系统编码创建后不可变，已发布系统采用草稿/新版本治理，不物理删除。

### 6.2 系统下工单服务列表

列：服务编码、服务名称、类型、发布状态、表单版本、流程配置状态、默认入口、更新时间、操作。

操作：查看、编辑草稿、发布/停用、表单与流程、关联/取消模块。子列表在 Drawer 或当前系统详情区域，不与系统创建表单同时平铺。

### 6.3 交互与权限

- 服务端分页是数据来源；浏览器不把“前 100 条”当全部数据。
- 每个写操作带 CSRF、Idempotency-Key、If-Match/版本；409 保留用户输入并提示刷新。
- 无权限动作不展示，但服务端仍逐次校验。失败不显示成空数据，部分写入失败强制重新读取。
- 账号、系统和目录页面统一使用 Element Plus Table/Form/Dialog/Pagination；移动端退化为可横向滚动表格和底部操作菜单。

## 7. 未来客户端模式

未来外部系统调用采用标准 OAuth 2.0 Client Credentials（RFC 6749 4.4），只用于已经与授权服务器建立信任的机密客户端：[RFC 6749 Client Credentials](https://datatracker.ietf.org/doc/html/rfc6749#section-4.4)。Spring Security OAuth2 Client 原生支持 Client Credentials：[Spring Security OAuth2 Client](https://docs.spring.io/spring-security/reference/servlet/oauth2/client/index.html)。

预留原则：

- 机器主体与人类账号分表、分角色、分审计动作；不能登录网页。
- scope 使用 `ticket:create`、`ticket:read` 等最小集合，并叠加组织/系统范围；对象权限仍由服务端校验。
- 客户端密钥只存密钥管理系统，支持轮换、过期和吊销；数据库只存 client ID、允许 scope 和密钥引用，不存明文 secret。
- 接口幂等、速率限制、请求签名/令牌受众、mTLS（如需）在接入具体外部系统时单独评审。
- 本批不实现自建 OAuth 授权服务器、不接受 Basic Auth 长期密码作为业务 API 凭证。

2. 后端本地账号、密码会话、账号管理、系统范围与迁移测试。

5. 真实 MySQL 迁移、并发抢单、普通用户/运维/管理员权限矩阵与浏览器验收。

## 9. 验收标准

- 未登录只能进入登录页；错误凭证无账号枚举；正确登录后 Session ID 变化，退出后旧 Session 失效。
- 普通用户可提单、看自己工单和已发布知识，不能进入后台或读取他人工单。
- 5 名运维账号只对各自负责系统进入候选列表；提交后显示 5 人，抢单并发仅一人成功，成功后详情只显示受理人。
- 运维人员不能抢其他系统工单；停用/锁定账号立即失去新动作资格。
- 系统和目录以分页表格呈现，新增/编辑在弹窗，操作列动作完整，错误/空态/409 可理解。
- 密码哈希、Cookie、日志、审计和响应安全测试通过；前后端全量测试与生产构建通过。

## 10. 实施与验收记录（2026-09-04）

已完成本地账号认证、账号管理、共享队列候选读模型和系统/目录表格化后台。真实 MySQL 已从 V45 前向迁移到 V46，未删除或改写现有工单。IAM/OIDC 代码保持可选兼容，但当前 local-dev 和正式 Compose 默认使用本地账号。

本地验收账号：`requester`、`ops01`–`ops05`、`admin`。密码仅 local-dev 默认为 `LocalDev-Only!2026`，可用环境变量覆盖；生产没有默认密码，首次启动由仓库外一次性引导变量创建管理员。

认证实测：未知账号统一失败；`requester` 登录后仅显示提单、工单和知识入口，直接访问账号管理会返回首页且服务端仍拒绝；`admin` 可查看 7 个账号及其角色/负责系统；`ops01` 为一线运维且系统范围为 ERP。密码使用 SHA-256 预哈希后进入 `{bcrypt}` 自适应哈希，避免 bcrypt 多字节截断；5 次失败锁定 15 分钟，停用/重置密码提升 sessionVersion，使旧会话下一请求失效。

抢单实测由自动化覆盖：共享队列冻结 5 名候选，申请人可以安全读取姓名/组织/职位；两个候选并发领取只有一个 CAS 成功，领取后 `acceptanceCandidates=[]` 且 PRIMARY 只剩受理人；非共享任务不返回候选。浏览器详情在领取前显示“可抢单人员（5）”，领取后显示“我（姓名）”。

管理端已使用 Element Plus 标准模式：系统查询/状态/组织/负责人筛选、分页 Table、固定操作列、新增编辑 Dialog、详情 Drawer、上/下架确认；选中系统后用第二张表管理工单服务。未知服务计数、更新时间和流程摘要显示“—/进入查看”，不伪造数据。现有接口返回当前授权范围最多 100 条后由前端分页；若数据超过 100 条，下一批需给系统/服务聚合接口增加服务端筛选、排序和总数。

验证结果：前端 45/45 且生产构建通过；后端 42 个测试套件、150/150 通过；OpenAPI/Compose YAML 和 diff-check 通过。真实页面截图位于 `output/playwright/local-account-management.png`。

已知边界：账号写接口要求 Idempotency-Key、唯一登录名和乐观锁，可阻止重复副作用，但尚未建立持久化幂等重放账本；丢失成功响应时会通过列表核对或得到冲突，不保证相同 key 重放首次响应。未来客户端模式仍只保留标准 OAuth2 Client Credentials 设计，不签发自制 Token。
