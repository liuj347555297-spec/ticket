# ITSupport 操作手册功能与页面对齐

## 参考与目标

依据用户提供的 ITSupport 系统操作手册 v1.9（2026 年 1 月），对齐日常使用步骤与管理页面。参考包括工作台、我的流程、事件/问题提报与处理、知识应用、报表和公告。原文与 119 张截图仅在本地临时目录用于核对，不复制企业真实人员、电话、域名及业务内容到产品或 Git。

当前使用本地账号密码。暂缓零信任、企微/移动宿主接入、企业 IAM 及客户端凭证对接；保持基本账号、系统范围、请求校验。页面使用现有 Element Plus，并保留系统/目录表格 CRUD 主线。

## 功能设计

个人工单草稿采用独立表保存草稿 JSON、创建/更新时间和版本，以当前账号为所有者；保存不发起 Flowable，不写正式工单、不上传附件。读取/更新/删除均校验所有者。发起仍经过正式表单/服务/系统有效性校验；成功创建后再删除关联草稿，不确定提交仍复用原提交请求。草稿附件提示需重新选择。

处理表单保存应有真实持久化，不能只把表单当视觉输入。字段包括事件来源、提出单位、现场支持、原因分类、处理说明/解决说明等，以当前工单与处理权限为边界，乐观锁保存。转办、解决、关闭按现有生命周期连接，手册的普通受理不能被无条件多一层审批替代。超出当前流程模型的事件转问题并挂起/问题关闭恢复、撤回、跨节点退回和传阅要明确实现状态，不能以近似动作冒充完成。

功能性 UI 保留主题/申请信息/动态业务字段/富文本和附件表，收拢重复卡片及技术说明。后台日志和接口详情不作为主要用户说明。

## 分工与验证

先完成本文，再并行：工作台与我的流程、工单处理、知识管理；主线程负责草稿箱、发起页、整体导航与账号联调。新数据库迁移从 V47 顺序分配，旧迁移不改。完成后前端构建、相关行为测试、MySQL/浏览器核对；提交上一轮尚未提交的账号/候选/CRUD 与本轮变更，推送 develop，快进或正常合并到 master，保留两个分支。

本地草稿、查询和个人配置只含用户明确输入的功能数据；不把参考手册内样例作为真实业务数据。密钥和截图不进提交。

数据库前向迁移：V46 本地账号，V47 个人工单草稿，V48 处理明细及默认审批策略退役，V49 知识收藏/草稿，V50 活动审批去重。已执行迁移不修改，后续补充使用新编号。原已发起审批继续按冻结事实处理，不因默认策略退役而被日常动作绕过。处理保存与转办、终态推进通过锁定当前流程状态协调。

草稿并发冲突保留当前正文，提供“另存为新草稿”，不覆盖其他标签页；权限刷新中断恢复时释放跟踪状态，继续保留离开保护。知识保存成功但提交审核失败时保留已保存 ID/版本，重试不创建另一份知识。

## 与原手册仍存在的明确差异

- 新建申请人由登录账号带入，暂未实现代他人提报、联系电话/地点编辑；流程配置字段可承载其他业务信息。
- 尚未实现事件转问题后自动挂起、问题关闭恢复原单、任意跨节点退回、真正传阅、满意度评价；现有工单关联和协办不能冒充这些功能。“未解决返回处理”已实现。
- 我的待阅当前是未读工单消息，不等同于手册传阅任务。导出为最多 5000 条的 CSV，不冒称 Excel 或后台异步导出。
- 知识已实现草稿编辑及审核发布；驳回/撤回、作废审批、专题、分享、纠错、积分/排行尚未实现。分类使用现有分类编码，不是独立分类树管理。
- 保留已有真实报表和公告，未增加手册全部专属统计口径、日历排程或企业移动客户端。零信任与外部身份对接按要求暂缓。

本批是日常操作和管理页面的功能性对齐，不声明整本手册一比一复刻。原手册和截图未纳入 Git；根目录离线部署手册同步迁移、账号及升级检查说明。
