# 内网工单系统调研结论与决策清单

**版本：** 0.1（需求访谈基线）  
**状态：** 待评审，未进入开发

## 1. 已确认的约束

| 维度 | 结论 |
| --- | --- |
| 服务对象 | 内网普通用户发起 IT 运维与服务类工单，重点覆盖页面卡顿诊断闭环 |
| 规模 | 约 50,000 用户，峰值约 1,000 并发；组织层级和分支较多 |
| 可用性 | 7x24；应用、异步任务、流程任务和集成任务均需高可用 |
| 部署 | Linux，满足信创国产化要求 |
| 安全 | 等保二级基线；全量操作审计、最小权限、内网边界控制 |
| IAM | 支持 LDAP/AD、OIDC/OAuth 2.0、SAML 2.0；组织机构字段同步；SSO 可在一期后启用 |
| 集成 | 监控告警、日志平台、CMDB、应用性能监控（APM） |
| 协作 | 抢单、主办/协办、会签、并行处理、交接班、内部评论、跨部门转派 |
| 知识库 | 支持导入、关联、检索、版本和审核；当前不接入 AI 能力 |

## 2. 核心设计决定

1. **一期采用模块化单体 + 独立异步工作进程。** 它比一开始拆分微服务更易于在信创环境稳定交付，同时通过清晰模块、事件表和接口契约为后续拆分保留边界。
2. **流程引擎选用 Flowable OSS，嵌入 Spring Boot。** 其 BPMN 2.0、多实例会签、服务任务、定时器和关系型数据库事务模型适合人工作单；具体国产数据库以 POC 结果为上线门槛。
3. **IAM 是身份与组织的唯一权威源。** 工单系统仅持有本地投影、权限映射与业务角色，不反向维护主数据；停用采用软禁用，不能物理删除历史人员。
4. **审批改为“按状态转换配置”，不默认每一步审批。** 提交、受理、常规处理中强制审批会阻塞故障处置。默认只在高影响、高权限、关闭和升级等风险动作审批，管理员可对任意流程节点启用审批。
5. **页面卡顿采集与本系统解耦。** 本系统保存采集软件提供的会话标识、时间窗、URL/页面标识、摘要指标和报告链接，不能直接采集浏览器数据或凭证。
6. **低代码配置平台纳入必备能力。** 范围限定为服务目录、结构化表单、流程、路由、审批、SLA/OLA、通知、标签和报表模板配置；以元数据和已发布版本驱动，不能成为绕过领域校验、权限和审计的通用代码执行平台。
7. **受控流程跳转纳入必备能力。** 仅用于纠偏、应急和受审计迁移；普通处理人不拥有“任意跳转”权限，所有跳转必须经后端授权、硬性节点校验、影响预览和追加式审计。

## 3. 上线前必须确认的决策项

| 决策项 | 需要确认的内容 | 影响 |
| --- | --- | --- |
| 信创技术栈 | 指定 Linux 发行版、JDK、数据库、中间件、CPU 架构及其版本 | 驱动、流程引擎 SQL、容器镜像和性能 POC |
| 可用性目标 | RTO、RPO、计划维护窗口、双机房/同城灾备范围 | 集群、备份、演练与成本 |
| IAM 契约 | 身份主键、增量同步协议、组织字段字典、离职/调岗语义 | 账号映射、权限回收、数据一致性 |
| 外部集成 | API、认证方式、限流、告警去重键、CMDB CI 编码、APM 报告协议 | 适配器和联调计划 |
| 通知渠道 | 内网邮件、短信、企业 IM、站内信的可用性和优先级 | 提醒与 SLA 升级闭环 |
| 数据策略 | 附件类型/大小、日志脱敏、工单与审计留存期限 | 对象存储、容量、合规 |

## 4. 需要避免的误区

- 不能把 IAM 同步结果直接当作工单处理权限；权限应由岗位、组织范围、服务目录和委派关系共同计算。
- 不能让协办人直接完成主办人的工单；协办人提交处理结果，主办人或流程批准人负责状态推进。
- 不能仅用“卡顿”文本分类；需绑定业务系统、页面、环境、采集会话和时间窗，才能关联日志/APM。
- 不能先承诺所有国产数据库均兼容；须以选定发行版、JDBC 驱动和流程引擎版本的 POC 结论为准。
