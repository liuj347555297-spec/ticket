# 系统服务目录与首页门户：需求与实施设计

## 1. 需求修正

目录的首要入口是业务系统，不是全局表单列表或通用故障分类。用户先选系统，再从该系统下选择需要发起的工单服务；同一系统可提供多个相同技术工单类型的服务，例如 ERP 的采购故障、财务故障和权限申请。每个服务具有独立名称、说明、表单版本以及流程发布关系。

示例结构：ERP → 采购报障（申请表 A、处理表 B、流程 X）；ERP → 权限申请（申请表 C、审批表 D、流程 Y）。工单类型 INCIDENT/ACCESS_REQUEST 等是技术分类，不是唯一的服务标识。模块是系统内可选的细分范围，不替代系统层级。

首页参考用户截图的信息结构：紧凑的工作指标与快捷入口；主体为系统切换、模块筛选、工单服务卡片；右侧保留真实公告与知识入口。不要放虚构服务、统计或硬编码“热门”数据；不照搬截图中的企业名称及未接入功能。

## 2. 领域与发布边界

- ServiceSystem：系统身份、组织范围、上架状态和模块。
- ServiceOffering：以独立 serviceCatalogItemId 标识的工单服务；拥有自己的说明、技术类型、表单定义与发布修订。系统通过受控映射组织多个服务。
- OfferingRelease（后续发布包）：系统/模块/服务入口引用一个不可变发布包；包冻结 BPMN 修订、全部表单修订及节点绑定。不能在系统层设置一张表单或一条流程使所有下属服务共用。
- 历史实例：冻结系统快照、服务身份、表单和流程版本，系统改名、映射变化或新版本发布均不回写旧工单。

当前兼容运行模式中，独立目录已有独立表单发布治理；自由 BPMN、多表单运行发布仍遵循文档 13 的 Phase B/C，不能把 DRAFT_ONLY 设计包挂成可执行服务。后台须明确展示这一区别。不同服务需要不同流程时，目标关系落在服务发布包，而非首页卡片配置。

## 3. 本批实施计划

1. 提供按已发布系统及可选模块读取服务目录的只读聚合接口，复用现有组织范围、映射优先级和目录发布校验。返回真实服务条目，不以全局前 100 条目录拼接导致丢失。
2. 首页替换静态快捷服务和静态指引为真实系统服务门户，支持系统搜索/切换、模块过滤、工单服务搜索与按技术类型分组。点击具体服务带上 systemCode、moduleCode、catalogId 到新建页。
3. 新建页仅将 URL 参数当作选择意图，重新读取系统、模块、映射和已发布表单；不能通过 URL 越权或使用过期配置。已填写内容不得被同路由参数变化或异步旧响应覆盖；本地草稿与新入口冲突须清楚提示。
4. 后台服务配置改为系统优先，集中提供系统下的工单服务与发布状态、服务独立表单配置入口；系统/模块设置、关联服务与兼容表单维护分区展示。现有发布审批与审计不绕过。
5. 验证多服务、模块覆盖/回退、空目录、接口错误、快速切换、非法入口、系统/服务停用和建单预选；已有工单和真实发布记录不为 UI 验收而修改。

## 4. 接口与交互规则

- GET `/api/v1/service-systems/{systemCode}/catalog-items?moduleCode=...`：服务端返回映射范围内、当前用户可见且已发布的完整服务条目数组（沿用公开 ServiceCatalogItem 契约）。无模块只返回系统级入口；模块有启用映射时采用模块映射，否则回退系统映射。草稿、停用或跨组织条目不能出现。
- 门户建单地址：`/tickets/new?systemCode=...&moduleCode=...&catalogId=...`；参数不包含表单正文、流程 XML、处理人或任意跳转 URL。
- 加载状态按区域独立显示；失败不显示成“没有服务”，不回退演示目录。身份和组织切换立即清空旧投影；系统/模块切换使用请求世代防止旧响应回填。
- 门户、旧目录读取、表单、字段字典、规则匹配与建单保存共享同一服务端组织可见性规则；受管目录未设置适用组织时不开放，直接 HTTP 请求和省略 systemCode 不能绕过。已有历史工单仍按原快照读取。无受管配置覆盖的旧种子目录维持兼容；受管草稿/停用配置不能回退为同 ID 种子。
- 手工切换系统/模块时清空上一个服务的业务字段与选项，保留用户已写的公共主题和正文；从另一个服务入口重新开始须明确确认清空主题、正文与待上传附件。同页面 URL 变化只提示新的入口，不自动覆盖输入。
- 发布入口不声称系统下所有服务必须使用同一表单/流程。各服务的独立 BPMN 发布关系由后续发布包实现；本批没有放开任意部署权限。
- 已上架系统当前没有“保持生产版本并编辑下一草稿”的接口，因此设置、模块和服务关联只读，不能引导以停用绕过编辑限制。后续发布包阶段须一并增加系统目录草稿/活动版本分离，使系统继续服务时可以提交下一版目录。

## 5. 验收标准

首页可从一个系统中看见多个真实已发布工单服务；点击后正确预选该系统和具体服务并加载对应表单。切换系统或模块不残留上一个服务内容。后台首先呈现系统维度，能够明确区分系统上架、工单服务发布及设计稿冻结。前端构建、自动化测试、相关后端权限/过滤测试及浏览器检查通过；未交付的自由流程发布能力明确标注。
