# 服务运营规则册

**状态：** 设计基线，服务目录上线前必须逐项落配置。

## 1. 状态与审批矩阵

统一主状态为：草稿、已提交、待分类、待分派、待受理、处理中、已解决、待用户反馈、已关闭、已撤销、已挂起。升级、协办、并行、会签、交接班、关联问题和关联变更均为主状态之外的运行记录，不能覆盖主状态。

每个服务目录必须配置状态转换矩阵，至少包含发起角色、审批方式、候选人规则、驳回去向、必填字段、SLA 影响、通知模板和审计事件。默认策略为常规事件快速处置；目录可对任何动作开启单人审批、会签、或签或逐级审批。P1 事件的受理、抢单、技术协办和恢复动作不等待审批，审批只用于风险控制、关闭确认和事后复盘。

## 2. 重大事件（P1）

P1 满足任一条件时启动：核心服务不可用、影响跨组织关键业务、影响范围达到目录阈值、存在数据安全风险，或服务经理人工判定。

| 角色 | 责任 |
| --- | --- |
| 事件指挥官 | 决定优先级、协调资源、批准恢复与降级策略 |
| 技术主责 | 组织应用、网络、数据库等技术处置与证据汇总 |
| 业务沟通人 | 维护影响范围、用户公告、恢复确认与管理层通报 |
| 记录员 | 记录时间线、关键决策、参会人员和行动项 |

启动后系统冻结影响范围、责任人与优先级快照，创建专属协作空间和固定通报节奏。恢复后必须完成恢复验证、用户公告、重大事件总结、问题单或已知错误关联；目录按风险定义 PIR 时限和关闭会签规则。

## 3. SLA、OLA 与服务时间

优先级由服务目录的影响度 x 紧急度矩阵计算，允许人工上调但必须记录原因与审批策略。每项策略定义：服务时间与节假日历、首响目标、解决目标、预警阈值、升级链路、自动关闭观察期、重开规则和允许暂停原因。

- 工单主 SLA 始于提交，首响完成后解决计时持续。
- 只有经目录允许的“等待用户、等待供应商、计划变更窗口”等原因可暂停；挂起审批、开始时间、恢复条件和累计时长必须审计。
- 协办或子任务可配置 OLA，但主单 SLA 不因协办而重置；OLA 先预警主办人与队列主管。
- 值班交接和转派连续计时；禁止以重新分派规避超时。

## 4. 值班、队列与升级

队列是责任边界，不等于 IAM 组织。每个队列应配置服务范围、技能标签、值班轮次、候补顺位、最大在办量、值班主管和升级链路。自动分派按服务、CI、地域、技能、值班可用性和当前负荷计算；无候选人、超容量、人员停用或拒单时，工单保留在队列并触发候补/主管升级，系统不得静默指定个人。

交接班由交班人与接班人确认，必须包含当前影响、未完成事项、下一步、关联证据、SLA 风险和回退方案。值班表变更、代理、强制接管和容量阈值均为受审计配置。

## 5. 告警与事件关联

告警使用“来源系统 + 指纹 + CI/服务 + 时间窗”生成关联键。规则必须配置去重窗口、抑制条件、自动建单阈值、自动恢复处理、关闭回写、重试和人工补偿。

一个事件可关联多个告警，多个重复告警也可归并到同一事件。告警恢复只产生“恢复建议”，不得直接关闭事件；由主办人依据用户或监控验证提交解决。告警关闭回写失败进入补偿队列，并向事件处理人展示降级状态。

## 6. 数据、审计与灾备运营

服务目录和工单应标明数据密级；正文、评论、附件和导出取其最高密级。下载、导出、批量查询和跨组织查看必须二次鉴权并记录用途、对象范围、水印、操作者和审批记录。附件须通过类型白名单、病毒扫描和内容检测后可访问；原件、处理版本和删除/归档事件均可追溯。

上线前须由业务确认 RTO、RPO、备份周期、附件恢复范围、通知最大延迟和演练频率。恢复演练至少覆盖数据库、对象存储、流程定时任务、Outbox 消息、IAM 同步和关键通知；结果进入审计与改进台账。

## 7. 知识运营

知识条目必须有责任人、分类、适用服务/CI、可见范围、密级、版本、审核状态、复审日期和来源。状态为草稿、待审核、已发布、已废弃；待审核或已废弃内容不得进入普通用户检索。

用户评价、失败搜索、重复工单和低首次解决率自动形成改进候选。已发布知识发生关联服务变更、连续低评价或达到复审日期时进入复审任务；当前不接入 AI 生成内容，所有知识由人工或受控导入形成草稿，并由具备范围权限的审核人发布。

## 8. 结构化提问、标签与规则预检

服务目录定义结构化问卷，优先使用枚举、级联选择、CI 选择、时间选择和可校验输入；自由文本只用于补充症状、复现步骤和已尝试处理。各服务必须明确最小字段集、可选字段、条件显示规则与脱敏提示，避免把诊断压力全部转移给普通用户。

标签分为系统标签、目录标签、人工标准标签和自由标签。自由标签格式为 `#标签名`，由用户或处理人添加；系统保存标签规范名、显示名、来源、创建人、作用域、审核状态和同义词。未审核的自由标签不参与自动分派、SLA 或权限决策，只参与检索候选；高频自由标签可由服务负责人提升为标准标签。

建单预检按“结构化字段和标签精确召回 -> 已发布知识与已解决案例关键词匹配 -> 服务目录规则重排”执行。适用范围匹配时，先展示可自助完成的短步骤；没有命中或结果不相关时不阻断提交。匹配只读取用户有权查看的已发布条目，不读取原始附件或敏感内容；每次推荐记录规则版本、证据、结果和用户反馈，并定期以自助解决率、采纳率、错误分派率和人工介入率复盘。
