# 服务运营规则册

**状态：** 设计基线，服务目录上线前必须逐项落配置。

## 1. 状态与审批矩阵

统一主状态为：草稿、已提交、待分类、待分派、待受理、处理中、已解决、待用户反馈、已关闭、已撤销、已挂起。升级、协办、并行、会签、交接班、关联问题和关联变更均为主状态之外的运行记录，不能覆盖主状态。

每个服务目录必须配置状态转换矩阵，至少包含发起角色、审批方式、候选人规则、驳回去向、必填字段、SLA 影响、通知模板和审计事件。默认策略为常规事件快速处置；目录可对任何动作开启单人审批、会签、或签或逐级审批。P1 事件的受理、抢单、技术协办和恢复动作不等待审批，审批只用于风险控制、关闭确认和事后复盘。

## 2. 重大事件（P1）

P1 满足任一条件时启动：核心服务不可用、影响跨组织关键业务、影响范围达到目录阈值、存在数据安全风险，或服务经理人工判定。

| 角色 | 责任 |
| --- | --- |
| 事件指挥官 | 决定优先级、协调资源、批准恢复与降级策略 |
| 技术主责 | 组织应用、网络、数据库等技术处置与证据汇总 |
| 业务沟通人 | 维护影响范围、用户公告、恢复确认与管理层通报 |
| 记录员 | 记录时间线、关键决策、参会人员和行动项 |

启动后系统冻结影响范围、责任人与优先级快照，创建专属协作空间和固定通报节奏。恢复后必须完成恢复验证、用户公告、重大事件总结、问题单或已知错误关联；目录按风险定义 PIR 时限和关闭会签规则。

## 3. SLA、OLA 与服务时间

优先级由服务目录的影响度 x 紧急度矩阵计算，允许人工上调但必须记录原因与审批策略。每项策略定义：服务时间与节假日历、首响目标、解决目标、预警阈值、升级链路、自动关闭观察期、重开规则和允许暂停原因。

- 工单主 SLA 始于提交，首响完成后解决计时持续。
- 只有经目录允许的“等待用户、等待供应商、计划变更窗口”等原因可暂停；挂起审批、开始时间、恢复条件和累计时长必须审计。
- 协办或子任务可配置 OLA，但主单 SLA 不因协办而重置；OLA 先预警主办人与队列主管。
- 值班交接和转派连续计时；禁止以重新分派规避超时。

当前 SLA 日历按不可变版本治理：新工单固化命中的日历键及版本，后续日历调整只能创建新版本并只影响后续工单。日历可定义时区、工作日、工作时段和节假日；暂停与恢复基于该历史日历延展截止时间。预警/违约扫描只产生可去重的 `SLA_WARNING` / `SLA_BREACHED` 运营事件和审计，不能自行改状态、改主办或绕过升级审批。

## 4. 值班、队列与升级

队列是责任边界，不等于 IAM 组织。每个队列应配置服务范围、技能标签、值班轮次、候补顺位、最大在办量、值班主管和升级链路。自动分派按服务、CI、地域、技能、值班可用性和当前负荷计算；无候选人、超容量、人员停用或拒单时，工单保留在队列并触发候补/主管升级，系统不得静默指定个人。

交接班由交班人与接班人确认，必须包含当前影响、未完成事项、下一步、关联证据、SLA 风险和回退方案。值班表变更、代理、强制接管和容量阈值均为受审计配置。

### 4.1 候选路由隔离

分类、分派、抢单、转办、协办、交接班和审批的候选人必须由服务端依次取交集：已发布路由/流程规则的候选角色、当前启用的 IAM 主体、当前启用的后台授权、覆盖目标工单组织/服务系统/服务目录/队列的 `DATA_SCOPE` 授权包、值班/技能/容量约束与职责分离规则。仅拥有支持角色、知道 IAM ID、曾是历史处理人或能查到某队列，均不构成候选资格。

候选查询只能从已授权的目标工单/任务发起，返回完成当前业务操作所需的最小字段和有界结果，不提供跨队列全员名册、候选总数、无权人员存在性或组织树反推。服务端在任务创建、抢单/分派提交、交接确认和审批决策时都须重新计算候选资格。候选快照用于审计和防止审批政策被事后改写，不能绕过当前 IAM 停用、调岗或范围撤销校验。无有效候选人时任务必须停留在受控队列并告警，不得降级为全局角色或任意管理员。

### 4.2 团队成员版本与审批三阶段复核

每次分派、值班、代理和审批政策都必须引用明确的队列授权版本（服务范围/成员政策）及团队成员版本。成员记录须与 IAM 投影版本、后台授权版本、有效期和职责类型关联；只有当前启用且完整范围覆盖目标工单的成员可被计入候选。IAM 停用/离职/调岗、后台撤权、成员到期/退组或队列授权更版必须触发候选缓存失效、待办重算与已在办责任重分派告警，不等待会话过期或定时全量刷新。

审批在三个阶段都使用目标工单的组织/系统/目录/队列事实复核：创建时计算并冻结合格候选集；展示/领取时只向当前仍合格的本人返回待办；决策/完成时同时校验冻结候选成员身份与当前 IAM、后台授权、`DATA_SCOPE`、队列成员和职责分离。申请人必须排除；对分派、授权、交接等使目标人直接获益的审批，拟受让/拟获益人也必须排除。排除由服务端生成且固化原因码，不接受客户端覆盖。

候选人查询不得变成团队目录接口：不返回被排除/无权人员、候选总数、跨队列页码或可以通过排序/响应时间猜测人员存在性的信号。创建、展示和决策三阶段分别记录候选政策版本、成员版本、范围摘要、排除摘要、结果和统一关联 ID。

### 4.3 队列迁移计划与失败关闭

队列迁移只能经过独立计划执行。计划须冻结源/目标队列、队列授权版本、选择规则或显式任务集、原因、预估数量、幂等绑定和计划版本。计划发起人不得同时作为审批人；审批人必须在审批当时具有源/目标队列管理范围，审批结果固化身份、范围/队列版本和决定原因。

执行不信任已批准计划中的历史权限。执行开始及每个任务比较更新前均重新验证：执行人当前权限，源/目标队列当前状态、服务范围与版本，工单当前组织/系统/目录/CI 范围，任务仍属源队列且为可迁移开放状态，目标队列容量，以及工单/任务乐观锁版本。目标队列不得因计划已批准而放大范围或静默创建成员关系。

迁移以任务为原子单元：成功或拒绝都须写入计划/批次/任务、源/目标队列及版本、工单/任务事前事后版本、执行授权摘要、结果和原因码。单任务校验失败时保持原队列、流程、主办和待办不变；发现执行人失权、队列版本/授权整体失效、计划被撤销或数据库故障时，立即停止后续任务并以 `BLOCKED`/`FAILED` 关闭。已成功任务保留审计事实，但不得将未执行/失败任务记为成功或无声跳过。

## 5. 告警与事件关联

告警使用“来源系统 + 指纹 + CI/服务 + 时间窗”生成关联键。规则必须配置去重窗口、抑制条件、自动建单阈值、自动恢复处理、关闭回写、重试和人工补偿。

一个事件可关联多个告警，多个重复告警也可归并到同一事件。告警恢复只产生“恢复建议”，不得直接关闭事件；由主办人依据用户或监控验证提交解决。告警关闭回写失败进入补偿队列，并向事件处理人展示降级状态。

## 6. 数据、审计与灾备运营

服务目录和工单应标明数据密级；正文、评论、附件和导出取其最高密级。下载、导出、批量查询和跨组织查看必须二次鉴权并记录用途、对象范围、水印、操作者和审批记录。附件须通过类型白名单、病毒扫描和内容检测后可访问；原件、处理版本和删除/归档事件均可追溯。

上线前须由业务确认 RTO、RPO、备份周期、附件恢复范围、通知最大延迟和演练频率。恢复演练至少覆盖数据库、对象存储、流程定时任务、Outbox 消息、IAM 同步和关键通知；结果进入审计与改进台账。

运营报表导出必须在服务端异步执行：任务创建时冻结查询日期、报告类型和经授权的数据范围；只有原申请人且下载时仍具有报表权限才能取得结果。文件内容、哈希、状态、失败码与下载次数均进入审计，浏览器不得直接从当前页面数据生成绕过授权的导出文件。

### 6.1 BOLA/IDOR 运营防护矩阵

| 对象/入口 | 必须使用的当前授权 | 防泄露要求 |
| --- | --- | --- |
| 工单详情、评论、关联、流程与待办 | 当前 IAM/后台授权 + 动作角色 + 组织/系统/目录/队列范围 + 对象关系/任务状态 | 篡改工单号、任务 ID、关联 ID 或历史参与人均不得证明对象可见；无权响应不泄露存在性、状态、组织或处理人 |
| 附件、知识原件与内联预览 | 父对象权限 + 文件用途 + 扫描/保留状态 + 下载权限 | 附件 ID、文件名、对象键和下载 URL 均不是授权；禁止返回存储地址或以不同错误猜测扫描状态 |
| 列表、队列、待办、未读与搜索 | 与详情相同的对象授权谓词，在数据库/索引查询前生效 | 分页、排序、聚合、搜索建议、总数和空页均只反映已授权子集，禁止先全量读取再在应用内过滤 |
| KPI、计数、分组汇总与排行 | 当前数据范围 + 受控指标口径 + 用途 | 分子、分母、零值、分组键和刷新时间都不得泄露无权组织/系统；小样本必须抑制或合并 |
| 导出、批量操作与长时任务 | 创建时授权范围快照 ∩ 执行/下载时当前权限 + 二次鉴权/用途 | 范围扩大或主体变更时任务失效；结果不可跨主体、跨范围、跨任务复用，且必须限时保留 |
| CI、告警、消息、审批与候选人搜索 | 父工单/任务权限 + 对象自身范围 + 当前身份状态 | 不得通过对象 ID、关键词、分页、候选总数、返回顺序或响应时差枚举他人/他组织对象 |

列表查询、详情查询、计数查询、搜索索引和导出任务必须复用同一份服务端授权谓词与授权版本，禁止为性能、缓存或统计另建放宽范围的查询通道。缓存键、搜索索引分区、报表汇总和导出文件必须绑定主体/授权范围摘要与授权版本；调岗、停用或范围撤销时主动失效。

### 6.2 授权与防枚举审计

角色/范围授予、撤销、停用、调岗收敛、候选集计算、路由失败、跨范围申请与所有敏感读取/导出必须记录追加式审计。授权判定摘要至少包含请求 ID、当前 IAM 主体与投影版本、后台授权版本、动作、资源类型/脱敏对象引用、命中的授权包/范围类型、允许/拒绝结果和稳定原因码。拒绝审计不记录无权对象的正文、附件名、人员名单或存储地址。

列表/搜索/计数审计记录规范化筛选摘要、范围摘要、返回数量和限流/截断结果，不逐条写入无界审计；详情、附件、敏感内联、候选人查询、跨范围和导出则须逐次留痕。对象号连续猜测、空页/总数探测、高基数关键词扫描和大量拒绝必须可聚合检测、限流并告警，但告警标签不得携带原始关键词或敏感对象标识。

### 6.3 幂等键绑定与敏感数据最小化

所有会产生业务副作用的可重试请求都必须把幂等键与已验证主体、受控操作编码、资源类型/资源标识和规范化请求指纹绑定。指纹只由影响业务结果的字段、目标和前置版本生成，对集合顺序、Unicode、时间和默认值稳定化。重试只能取得本主体在同一操作/资源上的首次结果；不同操作、资源或指纹复用同一键时冲突且不执行。另一主体不得借用相同键获取或探测他人记录。

幂等记录和审计只保存键/主体/操作/资源的必要摘要、规范化指纹、结果引用/状态、时间与原因码。不保存请求原文、评论/知识正文、附件内容/文件名、密码、令牌、Cookie、恶意样本、外部回执或完整个人信息。低熕敏感值不得用无盐哈希伪装脱敏存储；使用平台受控密钥的 HMAC 或组合规范化后的不可逆指纹。幂等记录与业务、审计/outbox 在同一原子边界提交，禁止出现“业务已成功但幂等记录缺失”或反向伪成功。

### 6.4 幂等租约恢复与 HMAC 轮换

`IN_PROGRESS` 记录必须有有界租约、所有者、到期时间、尝试次数和心跳/续约上限。未到期重试不执行；到期后由单一节点以 CAS 接管，接管前先对账同一主体/操作/资源/指纹的业务、审计与 outbox。已成功只补齐记录和重放安全结果；能证明未执行才重试；无法确定则进入人工对账/最终失败，绝不猜测执行。

运维必须演练节点在预留后、业务提交前/后、幂等完成后响应前崩溃，以及两节点并发接管。验收标准是业务、审计和 outbox 各有效一次，不丢失已成功结果，不重复副作用，不跨主体重放。

HMAC 密钥由受管密钥系统按环境注入，有效密钥材料不少于 32 随机字节。幂等记录保存非敏感 `keyVersion`，不保存密钥或完整 secretRef。新版本先以只验证模式发布，再切换新签发；旧版本只验证未到期历史记录，等租约/保留期清窗后撤销。轮换、验证失败、未知 `keyVersion` 和旧密钥撤销都须告警并留审计，但日志/指标/审计/错误中不得出现密钥、完整引用或 HMAC 中间值。

### 6.5 V42 历史行清理与启动准入

V42 无 HMAC 版本的历史记录须在业务写流量开放前分类。旧 `IN_PROGRESS`、无强结果引用或业务/审计/outbox 证据不一致的记录进入人工对账；已成功记录仅保留历史证据，不自动换签为当前密钥版本。处置需操作人与复核人分离，逐条记录证据摘要、判定、最终状态和批次；禁止填充当前 `keyVersion`、伪造结果引用或重构请求原文。

上线门禁必须产出两个零计数证据：全表 `keyVersion IS NULL` 为零；状态为 `IN_PROGRESS` 且缺少非历史 `keyVersion`、租约 owner 或租约到期时间的旧活动记录为零。未达零不得启动写接口/工作者，不得仅靠应用层 fail-closed 带病上线。

状态查询仅向原主体返回操作/资源摘要、状态、尝试次数、租约到期、安全结果引用和原因码。不返回指纹、原始幂等绑定、租约 owner、`keyVersion`、secretRef、密钥或对账原始证据；无权主体按防枚举策略响应。

### 6.6 附件扫描生产运营

生产附件入口和扫描工作者必须绑定真实受管扫描器，扫描器未配置、健康失败、病毒库超出新鲜度阈值或仍为开发/空实现时不得接入写流量。运行中扫描器不可达、超时、断连、回执不完整/超限或结果未知时，当前和后续文件均保持 `SCAN_UNAVAILABLE`/隔离，附件下载、预览、内容抽取、知识导入/发布和消息投递继续关闭；不得以排队积压、业务紧急、管理员角色或人工修改数据库为由放行。

ClamAV 网络只允许应用到固定扫描端点，端点、协议、DNS 和代理不接受业务配置；连接、读写和总时限、并发/队列、文件字节数、解压后大小/层数以及回执字节数/行数均有硬上限。恶意命中直接隔离并告警，扫描服务恢复后也不得自动把旧 `SCAN_UNAVAILABLE` 视为通过，必须由受控重扫取得明确干净终态。扫描器身份和凭据与 IAM、对象存储、消息通道、幂等 HMAC 密钥分离，轮换互不影响。

值班告警至少区分恶意命中、扫描器不可用、病毒库过期、超时/断连、响应异常、队列积压和隔离处置逾期。审计仅保存文件不可逆摘要、父对象脱敏引用、扫描器/签名版本、规范化结果与原因码、耗时、重扫/处置主体和关联 ID；禁止保存恶意样本、附件正文/文件名、原始回执、隔离路径、端点或密钥。解除隔离须双人复核且只能进入受控销毁、取证移交或重新扫描，不得人工改成 `SCAN_PASSED`。

### 6.7 前端草稿、仪表盘与交互安全

前端草稿属于终端侧敏感数据，不是服务端业务事实。默认只保存在页面内存；首期仅允许当前标签页会话存储系统/目录及明确非敏感的布尔、枚举、日期选项，并按组织、IAM 主体及表单发布版本隔离。主题、自由正文、自定义标签、凭据、完整个人信息、内部评论、附件/文件名/文件句柄、导出内容或高密级正文绝不持久化；TTL 最长 24 小时。提交、放弃、到期、登出、会话失效、用户切换、调岗撤权或表单版本失配立即清除本标签页草稿和 capability；未来跨标签/跨设备草稿必须由服务端签发命名空间和不可延长的绝对过期时间。

capability/allowedActions 仅用于界面展示，不能改变后端角色、数据范围、流程状态或对象关系。缓存必须绑定主体、资源、授权/对象版本并短时失效；未知、过期、请求失败或切换用户时敏感按钮默认隐藏/禁用。运营不得把“按钮不可见”作为权限验收证据，也不得因按钮被前端篡改为可用就认为动作获准；所有写入及敏感读取仍以后端逐请求鉴权和审计为准。

仪表盘对 `UNKNOWN`、`PARTIAL`、`STALE`、超时、无权限和无数据分别展示明确状态、授权范围摘要与最后成功刷新时间；未知或部分数据不得归零、补齐、沿用为当前值，也不得显示“运行平稳/无告警/全部达标”等绿色结论。无权数据不通过空卡片、分组名、趋势断点、刷新时间差或错误文案暴露；状态恢复后必须重新取数，不能直接把旧缓存标成最新。

表单错误只指出当前可见且本次提交的字段，授权/对象/隐藏字段错误使用稳定防枚举提示并提供脱敏请求 ID，不显示原始响应、堆栈、内部字段/目录/人员、数据库/存储细节或用户输入原文。键盘和读屏操作须与鼠标遵循同一 capability、确认和后端鉴权：隐藏动作移出焦点顺序与可访问树，快捷键在输入法组合、文本输入和弹窗中不得触发提交、审批、删除等动作，危险动作要求明确确认且不能由 Enter 连击重复提交。移动端不得用悬停承载安全说明或把关键操作挤到重叠区域；主/次操作保持足够间隔，横竖屏、缩放、软键盘和返回导航不能造成误触、重复写入、显示他主体缓存，敏感内容不进入 URL、系统分享、剪贴板或通知预览。

## 7. 知识运营

知识条目必须有责任人、分类、适用服务/CI、可见范围、密级、版本、审核状态、复审日期和来源。状态为草稿、待审核、已发布、已废弃；待审核或已废弃内容不得进入普通用户检索。

用户评价、失败搜索、重复工单和低首次解决率自动形成改进候选。已发布知识发生关联服务变更、连续低评价或达到复审日期时进入复审任务；当前不接入 AI 生成内容，所有知识由人工或受控导入形成草稿，并由具备范围权限的审核人发布。

当前平台已将知识导入、版本上传、审核发布和归档落实为受控服务端动作：管理人员查看待审核队列并审核指定版本，普通人员仅能看到已发布条目。浏览器正文只允许读取已发布、扫描通过且受大小限制的纯文本版本；PDF、隔离、扫描拒绝和未发布文件不返回直链、文件内容或替代性“摘要”，从而避免把尚未审核的材料暴露为知识。

已发布知识默认进入定期复审周期，责任人和复审日期作为运营元数据保存；低评价、复审到期或人工标记会进入管理复审候选。评价是单用户、单知识版本的结构化“有帮助/需复审”反馈，不能提交自由正文或影响当前版本的访问授权。由工单形成知识时，仅允许后台经理从已解决/关闭工单创建待审核草稿，并且只能带入受控标题、目录与来源编号；正文、内部评论、附件和身份快照均不得自动复制。

### 7.1 组织/目录归属与同一范围谓词

知识文档的归属组织和已发布服务目录为必填、服务端受控属性。所有版本、导入任务、审核意见、预览/下载制品、复审任务和反馈都必须绑定文档归属快照，不得在子接口中另行猜测。任何归属变更都是新草稿版本和新审核流程，已发布版本与历史反馈快照不回写。

知识列表、搜索、详情、草稿、版本、导入、审核队列、审核决策、发布/归档、预览/下载、复审和反馈必须复用同一份“当前角色 + 组织范围 + 服务目录范围 + 文档/版本/扫描状态”谓词。普通人员只能看到当前范围内已发布内容，并且只能对当前可见的具体发布版本反馈；知识管理人和审核人也必须具有相同组织/目录范围，角色不代表全局。审核人不得审核自己创建/导入的草稿或归属变更。

### 7.2 历史空归属与迁移运营

归属组织或服务目录为空、已停用、未发布或无法唯一映射的历史知识统一标记为 `OWNERSHIP_MIGRATION_REQUIRED`，不进入普通检索、管理草稿列表、审核队列、预览、复审候选和反馈统计，也不允许发布或归档。平台管理员和审计员不因角色获得业务正文/原件；迁移操作员只能看到完成映射所需的脱敏元数据。

迁移必须是独立受控作业：干运行生成候选组织/目录和歧义清单，由知识业务责任人与安全/数据责任人双人复核，分批写入并支持按批次回退。每个文档的迁移事件须保存原归属摘要、目标归属、映射规则/脚本版本、申请/复核人、批次、事前/事后版本、结果/失败原因、时间和回退关联，并进入不可篡改审计。禁止默认归到创建人组织、全局目录、首个匹配目录或平台管理员范围。

## 8. 结构化提问、标签与规则预检

服务目录定义结构化问卷，优先使用枚举、级联选择、CI 选择、时间选择和可校验输入；自由文本只用于补充症状、复现步骤和已尝试处理。各服务必须明确最小字段集、可选字段、条件显示规则与脱敏提示，避免把诊断压力全部转移给普通用户。

标签分为系统标签、目录标签、人工标准标签和自由标签。自由标签格式为 `#标签名`，由用户或处理人添加；系统保存标签规范名、显示名、来源、创建人、作用域、审核状态和同义词。未审核的自由标签不参与自动分派、SLA 或权限决策，只参与检索候选；高频自由标签可由服务负责人提升为标准标签。

建单预检按“结构化字段和标签精确召回 -> 已发布知识与已解决案例关键词匹配 -> 服务目录规则重排”执行。适用范围匹配时，先展示可自助完成的短步骤；没有命中或结果不相关时不阻断提交。匹配只读取用户有权查看的已发布条目，不读取原始附件或敏感内容；每次推荐记录规则版本、证据、结果和用户反馈，并定期以自助解决率、采纳率、错误分派率和人工介入率复盘。
