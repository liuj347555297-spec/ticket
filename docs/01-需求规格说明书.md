# 内网 IT 工单系统需求规格说明书

## 1. 目标与边界

系统为内网普通用户和 IT 服务团队提供统一服务台，处理页面卡顿、系统故障、账号权限、软件安装、网络、设备和一般服务请求。目标是提高受理可见性、缩短恢复时间、建立可审计的处理协作和可复用的知识沉淀。

不在当前项目范围：浏览器端性能采集软件、AI 自动生成知识正文或自动理解能力、对 IAM 主数据的编辑、CMDB 主数据维护。系统通过接口关联已有平台能力。

## 2. 角色与权限

| 角色 | 主要权限 |
| --- | --- |
| 提单人 | 提交、补充、撤销本人未受理工单；查看本人及被授权范围的进度、评价与知识文章 |
| 一线支持 | 服务目录受理、抢单、分类、初步诊断、转派、协办、处理及知识候选提交 |
| 二线支持 | 处理专业队列、高风险变更审批前技术评估、并行子任务与根因补充 |
| 主办人 | 对处理结果负责；统筹协办和子任务；发起升级、挂起和关闭申请 |
| 协办人 | 处理被分配的协作事项，提交结果、附件和内部评论；不越权关闭主单 |
| 审批人 | 按流程策略审批指定的状态转换和会签任务；仅见与职责范围相关数据 |
| 主管/服务经理 | 队列、SLA、升级、人员工作量、报表和委派管理 |
| 平台管理员 | 服务目录、流程版本、权限策略、IAM 映射、字典、集成与审计查询；不可篡改审计记录 |

权限采用 RBAC（岗位角色）+ 数据范围（组织、服务、队列、CI）+ 委派规则组合。默认拒绝，所有越权访问记入审计。

## 3. 功能需求

### 3.1 工单与服务目录

- 服务目录可配置工单类型、必填字段、优先级、默认队列、流程版本和审批策略。每项服务还必须指定服务负责人、支持组、服务时间、数据密级、SLA 策略和下线日期。
- 平台提供受控低代码配置：服务目录、表单字段与分组、联动/校验规则、标签、路由、审批、SLA/OLA、通知模板、流程事件和报表模板均通过元数据配置、版本化发布和回滚实现。表达式只允许使用白名单变量和函数，禁止配置任意脚本、SQL、文件路径或外部网络请求。
- 一期将运行对象区分为：事件（Incident，恢复非预期服务中断或性能下降）、服务请求（Request，标准服务交付）、权限申请（Access Request，受控授权）、问题（Problem，根因和已知错误）与变更（Change，受控技术变动）。问题和变更一期可先作为关联对象和受控入口，但不得用普通工单的关闭规则替代审批。
- 每张工单拥有稳定编号、来源、影响范围、紧急度、优先级、服务/CI、状态、时间线、附件、订阅人和关联记录。
- 支持模板、草稿、批量导入、相似工单提示、合并/拆分与父子工单。
- 建单表单遵循“结构化优先、自然语言补充”原则：服务目录为每种请求提供标准选项、必填字段和动态校验；文本描述仅用于补充上下文。页面卡顿至少使用业务系统、功能/页面、环境、发生时间、影响范围、现象、频率、已尝试操作等结构化字段。
- 支持标准标签和自由标签。标准标签由服务目录、CI、告警、规则或人工选择产生；自由标签采用 `#标签名` 形式，例如 `#核协E`、`#扫码`，需记录来源、创建人、适用范围和审核状态，不能作为唯一的授权、审批或 SLA 判断依据。
- 用户提交前，系统以结构化字段、标签和脱敏文本检索已解决工单与已发布知识，返回相似度、适用范围、解决摘要和跳转链接；用户可“按指引自助解决”“仍需提交”或“反馈不相关”。
- 页面卡顿工单应至少包含：业务系统、页面/URL 标识、发生时间窗、用户网络/终端摘要、影响范围、性能采集会话 ID、采集报告地址、APM Trace/事务 ID、日志检索链接和脱敏说明。

### 3.2 状态与默认审批策略

状态集合：草稿、已提交、待分类、待分派、待受理、处理中、已解决、待用户反馈、已关闭、已撤销、已挂起。升级是独立的协同/可见性标记与升级记录，不作为替代主状态的终态。

| 转换 | 默认执行者 | 默认审批 | 说明 |
| --- | --- | --- | --- |
| 提交 -> 待分类 | 提单人 | 可配置 | 服务目录校验后进入队列；高风险服务可启用受理前审批 |
| 分类/分派/受理/处理中 | 服务台或处理人 | 可配置 | 默认快速处置；目录可对指定转换启用单人、会签或或签审批 |
| 转派、协办、并行子任务 | 主办人或有范围权限者 | 可配置 | 记录原因、接收方和前后责任人；高影响事件可要求主管确认 |
| 处理中 -> 已解决 | 主办人 | 可配置 | 必填解决方案、验证证据和知识候选；高影响事件可要求关闭前会签 |
| 已解决 -> 待用户反馈 | 系统 | 否 | 通知提单人，等待用户确认或在目录定义的观察期内复核 |
| 待用户反馈 -> 已关闭 | 系统/提单人/服务台 | 可配置 | 用户确认或超期自动关闭；自动关闭前须提醒并允许补充 |
| 重开 -> 处理中 | 提单人或服务台 | 可配置 | 保留原解决方案与 SLA 规则；重开原因、次数和时限受目录控制 |
| 挂起/恢复、升级/解除升级、撤销 | 有范围权限者 | 可配置 | 挂起仅使用允许原因；审批、SLA 暂停和通知按策略在执行时计算 |

审批策略按“服务目录 + 优先级 + 风险标签 + 状态转换”配置，可选择单人、会签、或签、逐级审批、超时升级和审批人代理。

流程支持**受控跳转**：流程负责人或经双人审批授权的平台管理员可将运行实例纠偏至已定义的目标节点。跳转前必须完成权限校验、目标节点白名单、必填字段校验、未完成任务处置、候选人重新计算、SLA 影响预览与通知预览；跳转原因、前后节点、操作者、审批人、实例版本和影响任务以不可修改事件记录。禁止跳过身份授权、高风险变更、关闭会签等硬性控制节点；禁止通过直接更新状态字段、流程表或数据库实现跳转。

### 3.3 多人协作

- 抢单采用原子领取：同一时刻只允许一位合资格人员成为主办人；失败者得到当前责任人提示。
- 主办人可添加协办人，协办任务有独立待办、期限和结果，主单仍由主办人推进。
- 并行工作使用子工单或 BPMN 并行任务；汇聚条件可配置为“全部完成”“任一完成”或“达到法定人数”。
- 会签支持指定人员、角色池、组织主管链和动态规则；审批快照固定审批人集合，组织变动不应改变进行中的责任归属。
- 交接班必须记录交接说明、未完成事项、附件、接班人确认和时间；交接后新主办人承担后续 SLA。
- 内部评论仅处理团队及授权主管可见；对用户公开的回复必须明确标记。所有评论、状态和责任变动生成不可修改的时间线事件。

### 3.4 集成、知识与报表

- 告警按来源系统、告警指纹和时间窗去重，可自动生成或关联工单；必须支持人工确认和关闭回写。
- CMDB 用服务和 CI 编码关联影响对象；CMDB 不可用不得阻塞人工建单。
- 日志/APM 提供深链接和关联标识；查询凭证由平台侧单独鉴权，不将日志正文批量复制进工单。
- 知识库支持 Markdown/HTML、分类、标签、版本、审核状态、导入、附件和工单关联；当前不接入 AI 生成或自动发布能力。
- 报表覆盖工单量、类型、SLA、首次响应、解决时长、重开率、积压、人员负荷、系统/部门分布、重复问题、知识命中率、重大事件恢复时长、告警噪声率和通知送达率。

### 3.5 规则分流与案例推荐

- 当前采用规则分流：服务目录、结构化字段、标签字典、CI、错误码与关键词精确匹配已发布知识和已解决案例；不接入 AI、模型或语义检索。
- 匹配结果必须展示证据：命中的字段、标签、案例状态、适用服务/CI 和最近复审时间。知识已废弃、无访问权限或数据密级不匹配时不展示正文。
- 标签、关键词、错误码、同义词、服务映射和排序权重均由平台管理员通过字典维护，支持模板导入、校验、版本发布与导出；字典修改必须审计并可回滚。
- 必须记录规则版本、命中证据、采纳/忽略/不相关反馈、最终分类和最终解决结果，用于评估命中率、自助解决率、错误分派率和人工介入率。

## 4. 非功能需求

- 在峰值 1,000 并发下，核心列表和详情接口 P95 小于 2 秒，建单/状态变更 P95 小于 3 秒；不含外部平台响应。
- 关键功能 7x24 运行；应用任一节点失效不丢失已提交事务。
- 所有写操作具备幂等键、乐观锁和审计事件；外部通知及同步采用可靠异步投递。
- 支持中文界面、无障碍基本要求、附件病毒扫描和全链路请求追踪。

## 5. 当前实现映射（开发增量）

- 工单中心已提供固定个人队列：我的待办、逾期待办、今日完成、我已办、我发起的、草稿箱、我的待阅和所有可见工单。调用方只可提交固定队列码，不能提交任意人员、组织或处理组作为筛选条件。
- 我的待办按服务端任务候选角色、候选人员和实际受理人计算；已办按已完成工作流任务计算；待阅按当前用户未读通知关联的工单计算；逾期按服务端 SLA 违约结果计算。
- 工单详情的动作按钮由服务端工作流读模型按当前身份、流程状态和主协办关系返回。前端不得根据状态自行拼接“受理、转办、协办”等写操作。
- 已接入的动作包括分类、分派、受理、抢单、转办、添加协办、交接班、挂起/恢复、升级、解决、关闭、撤销、重开和内部评论；写入仍在服务端重新进行对象鉴权、状态机校验、IAM 有效性校验、乐观锁和审计。
- 已提供受控的“关联工单”读写能力：仅允许 `关联`、`重复于`、`父工单`、`关联问题`、`关联变更` 五类关系；创建时校验源单可修改、目标单可读，读取时逐条重新校验两端对象权限。关联不改变任何一张工单的状态、审批或 SLA，重复提交同一关系按自然键幂等，所有成功尝试均写入审计。
- 工作流主办/协办在领取、分派、转办和添加协办时固化 IAM 身份、组织、岗位与快照时间；详情仅返回当前有效协作关系，处理记录仍以历史事件留痕，人员后续调岗不会改写已捕获的责任事实。
