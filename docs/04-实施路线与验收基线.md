## 2. POC 验收指标

- 50,000 身份和组织记录可完成全量导入、增量更新、调岗和停用回放；身份和组织数据无重复/循环，失败项可重试和审计。
- 四类 BPMN 场景可运行：抢单、主协办、并行子任务汇聚、会签审批；流程版本升级后历史实例仍可完成。
- 峰值 1,000 并发下，核心接口达到需求规格的 P95 指标，且没有重复领取、丢失状态或未审计写入。
- 单应用节点、单异步工作者故障以及数据库主备切换后，已提交工单、待办和定时任务可恢复，异步通知可去重重放。
- 在目标信创环境完成部署、漏洞扫描、基线核查、备份恢复和等保二级控制项检查。

## 3. 评审与治理

1. 需求评审：服务目录、字段、状态、审批策略、SLA、数据留存由运维、服务台、安全和业务代表共同签字。
2. 架构评审：信创产品版本矩阵、网络拓扑、容量、RTO/RPO、集成契约、安全边界完成确认。
3. 流程评审：每个服务目录至少有 BPMN 图、责任矩阵、异常/回退规则、超时规则和版本负责人。
4. 上线评审：压测、故障演练、恢复演练、权限测试、审计抽查、离线依赖与回滚方案全部通过。

## 4. 下一轮访谈所需材料

## 6. 生产可用开发基线（自 2026-08-22 起执行）

后续开发以可上线能力为目标，不再以界面占位、前端推断、内存模拟、直接更新业务表或“后续再补安全控制”作为功能完成标准。每一项流程或审批能力必须同时具备：已发布且可追溯的 BPMN/DMN 版本、数据库迁移与回滚说明、服务端对象/数据范围授权、幂等与并发控制、审计与脱敏日志、失败补偿或明确的失败关闭策略、单元/接口/MySQL 回归证据，以及对应需求、架构、流程和 OpenAPI 文档。

受控跳转执行进入生产实现前，必须完成以下门禁：审批 Flowable 实例已结束且结论为通过；申请、审批、目标节点和实例版本均一致；目标节点位于已发布的纠偏白名单；硬审批/会签/授权节点不可跨越；当前任务处置、候选人重算、SLA/通知影响预演和事务回滚方案均通过。任一门禁失败时只保留申请与审计，不改变工单或流程实例。

### 7.1 P0 协作、知识与消息闭环（V27）

- **交接班确认：** `HANDOVER` 不再直接改变主办人。服务端冻结接班 IAM 用户、工单/流程版本与理由，并启动 `servicehubHandoverConfirmation` Flowable 实例；只有指定接班人确认且快照仍有效时，主办关系才变更。拒绝、调岗/停用、越权、流程已变化或版本失效均安全关闭并保留审计、通知和处理记录。
- **知识库：** 已实现审核队列、版本上传、发布和归档。普通人员只能检索已发布文档；正文预览仅开放给已发布、扫描通过、大小受限的 `text/plain` 内容，PDF、隔离和拒绝文件没有浏览器直链或伪造预览。
- **消息投递：** 站内信先持久化为强制兜底；WPS IM 仅经受管适配器异步投递。Outbox 使用短事务认领、租约恢复、指数退避和最终失败状态；未配置经批准的 WPS 凭据/端点时不会伪造外部送达成功。组织→通道路由在服务端按当前 IAM 组织（可含下级）解析。
- **回归证据：** 本轮后端全量 `mvn test` 为 61 项通过，前端 `npm run build` 通过。V27 是唯一新增业务迁移；空库初版已同步为 V27，V26 初版作为历史演练基线保留。

### 7.2 P0 高风险生命周期审批（V28）

- `HOLD`、`ESCALATE`、`CANCEL`、`REOPEN` 已不再直接改变业务状态；发起时建立独立的生命周期审批申请，并冻结动作、理由、申请人、源工单/流程版本、Flowable 具体定义及审批候选人集合。
- 审批使用独立的 `servicehubLifecycleActionApproval` BPMN，不复用受控跳转表或其执行入口。仅冻结候选人且通过当前工单对象审批授权的人员可决策；申请人自审被拒绝。
- Flowable 实例结束后，服务端重新核对源版本。批准且未变化才执行对应动作；版本变化落为 `STALE`，没有浏览器可调用的“直接执行”接口。全部申请、决定、执行/失效及通知均留审计证据。
- 回归证据：后端全量 `mvn test` 为 62 项通过，前端 `npm run build` 通过。V28 是纯新增表迁移；当前空库默认初版为 V28，V26/V27 初版仅保留用于历史演练。

### 7.3 P0 协作确认、审批扩展与 SLA 运营（V29–V31）

- **生命周期审批扩展（V29）：** 分派、受理、解决、关闭也进入独立 Flowable 审批。分派对象由服务端校验、冻结并持久化；通过前不创建主办关系或向目标人员发送分派成功通知。批准执行时重验人员、工单与流程版本，任一变化即失效。
- **协作与代理（V30）：** 添加协办改为指定候选人的 Flowable 确认；确认前不授予协办权限。代理仅允许当前主办创建、不可自授、最长 30 天且每次操作重新校验 IAM 活跃支持角色与有效期；代理不改变主办人，也不绕开审批流程。
- **SLA 与运营（V31）：** 工作日历采用不可变版本，新单固化 `calendarKey@version`，支持时区、工作日、工作时段与节假日；预警/违约扫描仅写幂等事件和审计，不直接修改状态。运营导出改为服务端异步任务，冻结创建时数据范围，且仅原申请人仍具报表权限时可下载并计数审计。
- **回归证据：** 后端全量 `mvn test` 为 64 项通过，前端 `npm run build` 通过。V29–V31 均为前向迁移；当前空库默认初版为 V31。

### 7.4 审批策略治理与外部接入边界（V32）

- **审批策略：** 生命周期审批策略可按动作、服务目录和优先级配置，并以发布版本冻结到新申请；支持 `ANY_ONE`、`ALL_OF` 与比例会签 `QUORUM`。超时扫描只安全过期 Flowable 任务并记录审计事件，绝不自动执行工单动作。
- **WPS IM：** 只使用受管应用配置、精确 HTTPS 白名单和受管密钥引用；TLS、禁重定向、受限响应和严格回执校验均在服务端实施。无凭据、异常回执或网络错误一律安全失败，站内信保持兜底。
- **CMDB/监控：** 回调限制为受管监控连接、精确来源 IP、HMAC、时间窗、nonce 防重放和白名单 JSON 信封；重复告警归一化，跨 IAM 组织 CI 关联被拒绝。当前只提供服务器计算的人工研判/建单建议。
- **回归证据：** 后端全量 `mvn test` 为 74 项通过，前端 `npm run build` 通过。V32 是纯前向策略与审计迁移；当前空库默认初版为 V32。

### 7.5 审批运营、知识运营与生产门禁（V33–V34）

- **审批工作台：** 受控跳转、生命周期审批、交接确认和协办确认统一按当前 Flowable 任务与工单对象权限展示；申请人自审和无权任务不展示，也不返回候选人/候选人数。策略后台支持草稿、发布、停用、乐观锁、审计及数据库级“同动作同范围仅一条已发布策略”约束。
- **知识运营：** 发布后自动生成复审周期，支持责任人、复审待办和单用户单版本的结构化评价。只有后台经理可从已解决/关闭工单创建待审核知识草稿，且不复制工单正文、评论或附件。
- **生产门禁：** 新增 SBOM、源代码/镜像/密钥扫描、部署配置校验、备份恢复、健康检查、优雅停机与只读 K6 压测工件。缺少 Syft、Trivy、Gitleaks、Docker、K6 或受管凭据时脚本安全失败，不宣称扫描或演练通过。

### 7.6 服务系统注册、目录路由与待办工作台（V35–V37）

- **目录节点路由：** V35–V36 建立目录 × 节点分派策略、策略快照与共享待办模式；事件单 Flowable v2 直接进入受理，系统随机、共享待办抢单和上一节点指定均由服务端按 IAM 活跃角色池校验。历史流程定义不被 v2 覆盖。
- **服务系统注册：** V37 建立系统、模块、系统/模块服务目录映射及工单系统快照表。后续接入页面联动前，先执行空库导入、映射完整性、退役历史保留和跨组织越权验证。
- **待办体验：** 提单页 IAM 身份改为只读信息展示；待办详情将重构为左处理表单、右协作沟通工作区。候选人选择、协办、内部评论、交接和抢单均需复用服务端对象授权与审计。
- **V38 服务系统治理：** 系统注册、模块、系统/模块目录映射、发布/退役和追加式生命周期事件已落地；前台按 IAM 组织只读联动，建单在同一事务重验映射并写入 `ticket_service_system_snapshot`。本地 MySQL 已完成 V38 迁移并以虚构 ERP/采购订单/页面性能目录联动验证。

## 8. 第一批 P0：集团范围授权与查询生产化

本批次先关闭集团生产使用的两个基础风险：数据范围未下推和工单集合无界查询。详细设计以 [`11-集团数据权限与工单查询设计.md`](11-集团数据权限与工单查询设计.md) 为准；文档、数据库迁移、服务端实现、OpenAPI 和生产证据必须在同一迭代收口。

### 8.1 交付顺序

| 阶段 | 交付 | 退出条件 |

### 8.4 安全验收门禁

- 两个组织使用相同标题、目录、系统名称和近似工单编号时，无权主体仍不能从详情、列表、搜索、数量、空页、导出、关联、审批或附件推断另一组织对象。
- 一线、二线、服务经理、审计员和平台管理员必须同时满足动作角色与显式数据范围；没有独立全局范围授权时，任何宽角色都不能查看全集团工单。
- 组织下级、服务、队列和 CI 范围分别验证精确命中、越界拒绝和组合规则；客户端提交范围、队列、排序、游标或总数参数不能扩大结果。
- IAM 停用、后台撤权、团队离队或范围版本变化后，下一次请求立即收敛；旧游标失效，旧会话不能继续读取或抢单。
- 共享队列并发抢单只有一个成功者；失败者重新读取服务端结果，不产生重复主办、重复流程推进或重复通知。

### 8.5 数据与容量验收门禁

- 迁移在生产等价数据副本上验证：回填前后工单总数一致、范围键完整、无孤儿队列/成员/任务关系，失败可停止并从已记录批次继续。

- 使用至少 1,000,000 张工单、50,000 个身份、500 个系统和 500 个团队队列进行容量测试；1,000 并发只读负载下列表 P95 `< 1s`、P99 `< 2s`、错误率 `< 1%`。
- 压测期间数据库连接池、CPU、内存、临时表、锁等待和慢 SQL 不越过经 DBA 签字的容量线；应用无随工单总量线性增长的单请求内存占用。
- 发布前完成旧版本应用读取新结构、迁移后新版本切流、索引异常回退和滚动升级演练。数据库迁移不可逆时只能采用已评审的前向修复，不得编辑 Flyway 历史或删除业务数据回退。

### 9.3 V40 迁移门禁

- 新表、外键、唯一键和索引在生产等价副本验证；成员时间区间、队列范围、任务 `queue_code` 和快照不得出现非法空值、孤儿或重复活动事实。

- 双写阶段逐任务比较旧路由事实与新快照；差异只记录脱敏 ID、版本和原因，不自动选队列。达到签字阈值后才切换读取，最后按类型收紧非空约束。

### 9.4 功能与安全验收门禁

- 构造至少两个组织、两个团队、三个队列、重叠服务/CI 范围、普通成员和主管，以及生效前、活动、过期、离队、停用成员；只有“活动成员 + 活动角色 + 人员范围命中 + 队列范围命中”的组合可看到或领取目标任务。
- 同一团队内多个组织范围取并集，不同范围类型取交集；队列范围不能替代人员范围，主管身份也不能绕过工单范围。伪造团队、队列、成员、范围、版本或候选 ID 安全拒绝且不泄露数量。
- 至少 50 个合资格并发请求领取同一任务，断言唯一成功、唯一主办、唯一有效领取事件、单次流程推进和无重复通知；数据库或 Flowable 故障时事务回滚后任务可重新领取。
- 成员离队/过期/IAM 停用/后台撤权后，下一请求立即失去目录、列表、领取和处理能力；队列停用后无新入队和新领取，历史快照保持不变，未领取任务进入受控治理清单。
- 修改团队名称、队列范围、成员、策略或系统映射后，历史路由快照逐字段不变；新任务使用新版本，运行中任务不被当前配置静默改写。
- 生命周期审批和受控跳转分别覆盖：创建时跨范围人员排除、申请人排除、冻结后扩权不新增候选、冻结后撤权/调岗在待办隐藏、直接调用决策被拒绝、恢复原范围也不得替代新的受控任务处置。
- 审批写接口必须同时校验冻结候选、当前 Flowable 任务、当前角色、目标工单当前上下文和当前范围；任一失败不得追加通过决定、改变申请状态或执行工单动作。

### 9.5 容量与运维验收

- 500 个团队队列、50,000 名 IAM 用户、1,000,000 张工单和不少于 100,000 个活动/历史队列任务下，团队列表与数量查询满足第一批 P0 的 P95/P99，且无全局角色池加载或应用层全量过滤。

### 10.2 开发任务

1. 所有队列创建、更新、激活、停用、预演批准和执行命令先原子保留 `(主体, Idempotency-Key)`，固化操作、资源和请求指纹；成功/失败响应写入脱敏稳定摘要并配置留存 TTL。

3. 批准使用非申请人的当前管理角色和两端数据范围；批准前重验计划未过期、两端配置未变化和阻断项为零。

5. 聚合明细结果推进 `COMPLETED/FAILED/STALE`；重复执行返回已有结果，可重试失败只重跑未完成项，最终失败要求新预演或人工治理。
6. 实现受控 TTL 清理、计划积压/租约过期/失败项告警、运维查询和审计关联；清理不删除业务迁移或交接证据。

### 10.3 幂等与状态机验收

- 相同主体、键、操作、资源和规范化请求并发 50 次，仅一次产生业务变更；其余得到同一成功响应或处理中状态。更换请求字段、操作、队列或主体后使用同键均冲突。
- 成功、可重试失败、最终失败、处理中、租约过期和 TTL 到期分别验证；客户端超时后以原键重放可得到真实结果，不重复审计、迁移、清单或通知。
- 迁移计划只能沿 `PREFLIGHTED → APPROVED → EXECUTING → COMPLETED/FAILED` 推进；越级、倒退、重复批准、申请人自批、双执行者认领和过期计划均失败关闭。
- 同一源队列并发创建两个活动计划时只有一个成功；已完成/取消计划不阻塞后续新预演，但旧计划不能被新计划重用或修改。

### 10.4 任务迁移验收

- 目标队列必须在四类范围上覆盖源队列；分别测试少组织、少目录、少系统、少 CI、混合交集、目标停用和目标版本变化，均不得创建可批准计划。
- 预演后任务被领取、完成、取消、版本变化、工单/流程推进或源队列变化时，该项 CAS 失败并使计划进入 `STALE/FAILED`，不能把新状态覆盖为迁移成功。
- 至少 50 个未领取任务批量迁移，逐项断言目标 `queue_code`、任务版本、迁移结果、路由快照和审计唯一；重复执行保持同一结果。
- 在办任务的主办、流程节点、SLA 和原队列事实不变；每项只生成一份 handover checklist。没有清单、主管、截止时间或未完事项摘要时计划不得完成。
- 迁移执行中并发抢单时，领取或迁移仅一个 CAS 成功；失败方根据任务当前事实重新治理，不自动撤销有效领取。

### 10.5 真实 MySQL 与回退门禁

- 在全新 MySQL 空库顺序执行 V1–V42 并启动应用；从当前数据库基线及至少一个历史基线登记点升级至 V42；从含大量 V40 团队/成员/队列/任务/路由快照的副本升级并核对行数与外键。
- 校验 Flyway 顺序、校验和、重复索引、字符集、JSON 字段、时间精度、唯一活动计划约束和幂等自然键；迁移失败必须停止发布且可用前向修复恢复。
- 对幂等点查、活动计划查询、计划明细扫描、未领取 CAS、在办清单和 TTL 清理保存 `EXPLAIN ANALYZE`，并在百万工单/十万任务规模下验证锁等待、事务时长和批次上限。
- 演练 V42 应用发布失败后的旧应用回退：旧应用可忽略新增结构；停止新计划认领；已成功项不回滚业务事实；未完成项按租约恢复。禁止删除 V42 表或修改 Flyway 历史。

| P0-4C：事务收敛 | 业务写入、结果引用与幂等完成同事务或可证明恢复 | 任一崩溃窗口都有确定恢复路径，不能靠盲重试判断 |
| P0-4D：HMAC/轮换 | 规范化 HMAC-SHA256、受管密钥、`key_version`、双读单写 | 新写单版本；旧记录可验证；退役旧密钥不激活历史命令 |
| P0-4E：发布回退 | MySQL V1–V43、历史升级、故障注入、密钥轮换和应用回退 | 数据、性能、安全和恢复证据全部通过 |

### 11.2 开发任务

1. 新增 V43 租约、尝试次数、密钥版本和结果资源字段；为活动租约扫描、资源对账和过期清理建立受控索引。
2. Reserve 使用数据库 CAS 写入/接管租约；活动租约重复请求返回明确冲突，过期租约必须先执行资源对账。
3. 为 CREATE/UPDATE/ACTIVATE/DEACTIVATE、迁移 PREVIEW/APPROVE/EXECUTE/RETRY/CANCEL 分别定义结果资源定位和请求指纹校验规则。
4. 将同数据库业务写入与幂等完成纳入同一事务；无法同事务的引擎步骤保存稳定命令关联，并实现只补终态的恢复器。
5. 实现规范化 HMAC-SHA256 服务、受管密钥加载、`key_version` 校验和当前/上一版本双读单写轮换。
6. 增加租约积压、对账失败、尝试次数、旧密钥使用和恢复结果指标；日志只记录命令/资源安全 ID 与原因码。

### 11.3 并发与崩溃验收

- 同一命令 50 个并发 reserve 只有一个租约所有者；活动租约期间其余请求均为处理中冲突，不进入业务服务。
- 模拟 reserve 后业务提交前崩溃：租约到期、对账无结果后仅一个接管者 CAS 成功，尝试次数递增一次。
- 模拟业务提交后、幂等完成前崩溃：接管者从结果资源证明首次提交，只补写 `SUCCEEDED` 和安全响应摘要，业务写入/审计/通知数量不增加。
- 结果资源存在但主体、操作、资源或指纹不一致时进入最终失败并告警，不能接管、覆盖或返回他人结果。
- 执行者失去角色/范围、资源版本变化或租约过期后继续写入均被拒绝；旧执行者不能覆盖新所有者完成的终态。

### 11.4 HMAC 与轮换验收

- 相同语义但对象键、集合顺序、空白、Unicode 或时区表示不同的请求得到相同规范化字节和指纹；任一业务字段变化得到不同指纹。
- 使用错误密钥、错误 `key_version`、不足 32 字节密钥、缺少活动版本和客户端伪造版本均失败关闭，不在错误/日志中泄露密钥或 HMAC 原文。
- 轮换期间新请求只写新版本，旧记录分别以当前/上一版本成功验证；撤下上一版本前必须证明无其活动租约且记录已终态/归档。
- 完成轮换后，用旧键提交新命令不能通过；已有旧记录仍按制度返回稳定结果或明确归档状态，不能被当作新命令执行。

### 11.5 MySQL 与回退门禁

- 在真实 MySQL 验证 V1–V43 空库、当前基线升级、V42 存量幂等/计划数据升级，以及包含活动/过期租约和多密钥版本记录的故障恢复副本。
- 保存主体+键查询、过期租约扫描、接管 CAS、结果资源对账、终态完成和 TTL 清理的 `EXPLAIN ANALYZE`；并发接管不得产生长锁等待或全表扫描。
- 演练新旧应用切换、业务提交/幂等完成各崩溃点、数据库主备切换和密钥轮换中断。回退旧应用前关闭写入口并收敛活动租约，V43 新列/结果引用/指纹保持不变。
- 不得以删除 V43 列、清空 `IN_PROGRESS`、重置尝试次数、改写 `key_version` 或恢复旧密钥写入来完成回退；修复只能前向追加。

## 12. 第五批 P0：历史幂等治理（V44）

### 12.1 交付顺序

| 阶段 | 交付 | 退出条件 |
| --- | --- | --- |
| P0-5A：历史盘点 | NULL 版本、状态、强结果引用和异常绑定清单 | 数量可复核，报告脱敏，队列写入和接管已暂停 |
| P0-5B：分类迁移 | `LEGACY_RESULT_ONLY`、`RECONCILIATION_REQUIRED`、`FAILED_FINAL` | 每条历史记录只有一个关闭式分类，无记录获得新执行权 |
| P0-5C：非空收紧 | `LEGACY_UNVERIFIABLE` 标记、`key_version NOT NULL`、状态约束 | NULL 为零；legacy 标记不属于 key ring；新写仍仅当前版本 |
| P0-5D：治理审计 | 人工对账流程、状态查询隔离、迁移审计摘要 | 不重写旧指纹、不重放 payload、不自动恢复租约 |
| P0-5E：启动回退 | V1–V44、历史样本升级、启动自检和旧应用回退 | 不理解 V44 状态的应用不能开放写入口 |

### 12.2 迁移与安全验收

- 构造 V42/V43 历史样本：成功且有强引用、成功无引用、活动/过期 `IN_PROGRESS`、可重试/最终失败、NULL/未知 `key_version`、错误资源绑定和残留响应正文。
- 有强引用成功记录只进入 `LEGACY_RESULT_ONLY`；状态查询返回最小结果引用，使用旧键重放不得返回 payload、不得调用业务服务、不得创建租约。
- `IN_PROGRESS` 和成功无强引用记录全部进入 `RECONCILIATION_REQUIRED`；历史失败全部进入 `FAILED_FINAL`。迁移前后的业务队列、计划、任务、通知和审计数量不增加。
- 所有历史不可验证记录使用 `LEGACY_UNVERIFIABLE`，当前/上一 HMAC 密钥均不能验证或接管；尝试伪造 `key_version`、重算指纹或改写状态均被数据库/服务端拒绝。
- `key_version` 收紧为非空后验证空库新写、历史升级、批量治理和 TTL 清理；legacy 状态不得被活动租约、重试、接管和 payload 重放 SQL 命中。

### 12.3 启动、审计与回退门禁

- 真实 MySQL 顺序执行 V1–V44；从 V42 与 V43 历史数据副本升级；分别验证迁移前后分类数量、约束、索引、Flyway checksum 和应用启动自检。
- 生产启动检查必须在开放写接口前完成：Flyway V44、NULL 版本为零、legacy 非执行、活动 key ring 合法。失败时只允许受控只读诊断，不允许以配置开关绕过。
- 每次批量处置记录变更批次、分类前后数量、记录 ID 哈希、操作/审批主体、原因和结果；人工对账的确认/最终失败分别追加审计，禁止直接 SQL 静默改状态。
- 回退演练证明旧 V43 应用在不理解新状态时保持队列命令关闭；V44 表数据和约束不删除、不降级状态、不恢复旧 payload。恢复只使用兼容补丁或后续前向迁移。

## 13. 第六批 P0：附件恶意内容扫描生产化

### 13.1 交付顺序

| 阶段 | 交付 | 退出条件 |
| --- | --- | --- |
| P0-6A：环境封闭 | `local-dev` bypass 隔离、生产受管扫描器 Bean 与启动探测 | 非本机环境无法注册 bypass；生产缺扫描器或探测失败时不开放附件写入口 |
| P0-6B：协议适配 | ClamAV INSTREAM TCP 适配器、受控网络参数、分块协议和严格响应解析 | `OK/FOUND/ERROR` 唯一映射；超时、异常、超长和未知响应全部 `SCAN_FAILED` |
| P0-6C：存储隔离 | `PENDING_SCAN/CLEAN/FOUND/SCAN_FAILED` 状态机、清洁区/隔离区和幂等搬运 | 只有授权通过的清洁区对象可下载；隔离、失败和不一致对象全部失败关闭 |
| P0-6D：生产验收 | 故障注入、容量、监控告警、签名库与恢复演练 | 安全、运维和业务负责人签字；证据不含附件正文或内部扫描器信息 |

### 13.2 开发与配置任务

1. 将本地跳过扫描实现限定为 `local-dev`，增加非本机 profile 装配回归；生产配置必须加载受管扫描器，启动时校验 host、port、连接/读取/总超时、最大响应和文件上限。
2. 实现 ClamAV INSTREAM 分块客户端：固定受控块大小、网络序长度、零长度终止块、累计大小限制、响应字节上限和严格终止/状态解析；连接不可跨异常请求复用。
3. 固化附件扫描状态机与隔离/清洁对象引用。上传先写隔离区，扫描成功后校验摘要并受控转入清洁区；失败、病毒命中或证据不完整不生成下载能力。
4. 下载、预览、知识解析和下游分发统一校验对象授权、`CLEAN` 状态、清洁区位置和摘要；不得仅凭文件名、数据库布尔值或存储 URL 放行。
5. 增加幂等重扫、对象/状态不一致补偿、隔离留存与受控销毁，并记录扫描引擎、签名库版本、稳定原因码、文件摘要和请求关联 ID 的脱敏审计。
6. 增加扫描延迟、失败率、病毒命中、协议错误、签名库陈旧、隔离积压和存储不一致监控；扫描服务故障期间保持新文件隔离并限速恢复积压。

### 13.3 安全与协议验收

- 证明 bypass 只在 loopback 的 `local-dev` 生效；以生产 profile 分别模拟无扫描器 Bean、缺 host/port、超短密钥式占位配置、DNS/连接失败和启动探测失败，应用均拒绝开放附件写入口，且不存在运行时绕过开关。
- 使用协议桩逐字节验证 `INSTREAM` 命令、网络序块长度、分块边界和零长度结束块；覆盖空文件、最大允许文件、超限文件、慢连接、半关闭、读取超时、截断、超长、多行、未知编码和额外响应内容。
- 严格验证 `OK → CLEAN`、`FOUND → FOUND`、ClamAV `ERROR → SCAN_FAILED`；连接异常、超时、解析错误、扫描器退出和资源耗尽全部为 `SCAN_FAILED`，任何异常路径都不产生清洁状态或下载地址。
- 伪造 host、端口、响应、状态字段、存储键、摘要和文件 MIME 均不能触发 SSRF、命令执行、日志注入或越权下载；响应和日志不得泄露内网地址、病毒特征全文、附件内容或异常堆栈。

### 13.4 存储、并发与下载验收

- 上传完成到扫描结束期间只能在隔离区读取且仅扫描服务账号可访问；普通用户、工单参与人、管理员和对象存储直链均不能下载、预览或索引 `PENDING_SCAN/FOUND/SCAN_FAILED` 文件。
- 模拟扫描成功后对象搬运前、对象搬运后数据库提交前、状态提交后响应前崩溃；重试不得重复创建可见对象，任何中间态均不可下载，补偿最终收敛到唯一清洁对象或隔离状态。
- 扫描时替换内容、摘要不一致、清洁对象缺失、隔离对象误放清洁区、状态被并发修改和重复扫描结果冲突均失败关闭并告警；不能以最后一次响应覆盖已有病毒命中证据。
- 下载时撤销角色、数据范围或对象关系后立即拒绝；清洁状态不能替代现有附件对象授权。隔离文件即使使用旧链接、预签名地址、缓存或相同文件名也不得读取。

### 13.5 容量、运维与回退门禁

- 在生产等价网络验证并发上传、最大文件和隔离积压恢复；记录 P50/P95/P99 扫描耗时、连接数、内存、带宽、超时和扫描器 CPU，应用不得因整文件入堆产生不可接受的 GC 或 OOM。
- 演练扫描器不可用、主备切换、签名库更新失败、对象存储短暂失败和网络抖动；新文件始终留在隔离区，恢复后按限速幂等重扫，既有清洁附件仍按授权策略服务。
- 发布证据包括生产 profile 启动门禁、网络白名单、配置脱敏、协议测试、隔离访问策略、故障注入、监控告警和误报处置审批。任一证据缺失不得宣称附件链路生产就绪。
- 应用回退前停止新上传并收敛在途扫描；若旧版本不能理解隔离状态或不能保证生产扫描器装配，则保持附件写入口关闭。不得通过批量改为 `CLEAN`、移动隔离对象或关闭下载鉴权完成回退。

## 14. 第七批 P0：前端体验支撑与流程产品化首批

### 14.1 交付顺序

| P0-7B：Dashboard 读模型 | scope、`asOf`、口径版本、逐指标 availability 和下钻映射 | 数量与下钻同范围；失败不以零值伪装；无跨组织枚举 |

### 14.2 开发任务

2. 建立 Dashboard 专用范围化查询与只读 DTO，为每个指标固化查询口径、`scopeDigest`、`asOf`、`availability`、安全原因码和下钻筛选；禁止读取全局汇总再前端裁剪。
3. 明确浏览器草稿白名单与清理策略；服务端草稿绑定主体、范围、目录、schema 版本、乐观版本和 TTL。附件独立进入隔离上传，草稿只保存无下载能力的临时引用。

### 14.3 功能与安全验收

- 以提单人、支持人员、队列主管、服务经理、审计员和平台管理员验证导航矩阵；调岗、撤权、离队和会话刷新后能力收敛。修改本地缓存或直接调用隐藏接口仍被服务端拒绝。
- Dashboard 构造同名跨组织工单、共享系统/CI 和无权队列；卡片、趋势、角标、空值、错误状态和下钻均不泄露无权数量。指标不可用返回 `UNAVAILABLE/DEGRADED`，不得返回误导性零。
- 同一响应的 `scopeDigest/asOf` 与下钻查询可追溯；授权版本变化后旧下钻/游标失效。Dashboard 查询只读、有限时，不触发领取、审批、通知或业务状态变化。
- 检查 localStorage、sessionStorage、IndexedDB、浏览器缓存、日志和前端错误上报，不得出现附件内容、预签名地址、token、Cookie、CSRF、幂等密钥或完整授权上下文。
- 草稿跨设备恢复、TTL 过期、并发更新、目录停用、schema 升级、撤权和临时附件过期均有确定结果；旧版本不能静默升级、丢字段或提交未发布字段。
- schema 恶意字段、脚本、远程组件、越权默认值、隐藏字段篡改和跳步提交均被服务端拒绝；步骤顺序不能改变流程或对象授权。
- 发布包必须唯一引用已发布目录/schema 和已部署且校验通过的流程定义；申请人自批、版本漂移、缺少兼容说明或路由/SLA 引用无效时不能发布。

### 14.4 兼容、发布与回退

- 首批接口采用可扩展字段和稳定枚举；旧前端可继续使用既有静态入口但不能因此获得新能力，升级窗口结束后移除角色推断。未知 capability、步骤或 availability 值必须安全隐藏并保留可诊断日志。
- 历史工单继续按冻结 schema/流程定义展示；历史 schema 若不再支持编辑，提供只读字段投影，不调用最新 schema 重解释。活动草稿升级只执行经审批的显式迁移函数并保留前后摘要。
- 发布顺序为能力/读模型兼容接口 → 新前端灰度 → 草稿/schema 版本切读 → 发布包映射启用。任一阶段失败可回退前端或关闭新入口，但不得改写历史工单、流程实例、schema 或发布包事实。
- 上线证据包括角色与范围矩阵、Dashboard 查询/下钻一致性、浏览器存储扫描、schema 兼容向量、发布包职责分离、真实 MySQL 性能和旧前端回退。未通过前不得宣称流程低代码化或前端体验生产化。
