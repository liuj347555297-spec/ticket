# 实施路线与验收基线

## 1. 分阶段范围

| 阶段 | 交付内容 | 退出条件 |
| --- | --- | --- |
| 0：调研与 POC | 技术矩阵、Flowable/国产数据库/IAM 压测、集成契约、原型评审 | 关键兼容性和性能风险已量化，有签字的选型结论 |
| 1：核心服务台 | IAM 组织投影、账号登录、服务目录、结构化表单配置、事件/请求/权限申请边界、建单、队列和值班、抢单、主协办、审批、SLA/OLA 计时、审计、基础报表 | 关键工单可闭环，权限与审计通过测试 |
| 2：集成与可靠性 | 监控/CMDB/日志/APM 适配器、告警关联、通知、重大事件、HA、备份恢复、压测、演练、低代码流程/规则运行时 | 达到可用性、性能和恢复验收标准 |
| 3：运营增强 | 知识库导入/审核/检索、可视化流程设计与版本治理、受控流程跳转、SLA 可视化配置、报表深化、SSO | 业务自助配置与运营指标稳定 |
| 4：运营规则增强 | 标签字典、案例匹配规则、知识运营指标与服务目录持续优化 | 规则版本、导入导出、审计与效果指标稳定 |

## 2. POC 验收指标

- 50,000 身份和组织记录可完成全量导入、增量更新、调岗和停用回放；身份和组织数据无重复/循环，失败项可重试和审计。
- 四类 BPMN 场景可运行：抢单、主协办、并行子任务汇聚、会签审批；流程版本升级后历史实例仍可完成。
- 峰值 1,000 并发下，核心接口达到需求规格的 P95 指标，且没有重复领取、丢失状态或未审计写入。
- 单应用节点、单异步工作者故障以及数据库主备切换后，已提交工单、待办和定时任务可恢复，异步通知可去重重放。
- 在目标信创环境完成部署、漏洞扫描、基线核查、备份恢复和等保二级控制项检查。

## 3. 评审与治理

1. 需求评审：服务目录、字段、状态、审批策略、SLA、数据留存由运维、服务台、安全和业务代表共同签字。
2. 架构评审：信创产品版本矩阵、网络拓扑、容量、RTO/RPO、集成契约、安全边界完成确认。
3. 流程评审：每个服务目录至少有 BPMN 图、责任矩阵、异常/回退规则、超时规则和版本负责人。
4. 上线评审：压测、故障演练、恢复演练、权限测试、审计抽查、离线依赖与回滚方案全部通过。

## 4. 下一轮访谈所需材料

- IAM 的接口说明、组织字段字典、样例脱敏数据，以及账号停用/调岗的实际规则。
- 信创软硬件清单：操作系统、JDK、数据库、Redis/MQ、容器平台、负载均衡、对象存储。
- 现行服务目录、工单样本、优先级定义、现有审批制度、值班与升级通讯录。
- 监控、日志、CMDB、APM 的接口文档与一个可脱敏的故障关联样例。

在这些材料齐备前，建议不冻结数据库、流程引擎具体补丁版本或外部接口实现；但本文档所定义的模块边界、审计原则和工作流模型可用于原型与评审。

## 6. 生产可用开发基线（自 2026-08-22 起执行）

后续开发以可上线能力为目标，不再以界面占位、前端推断、内存模拟、直接更新业务表或“后续再补安全控制”作为功能完成标准。每一项流程或审批能力必须同时具备：已发布且可追溯的 BPMN/DMN 版本、数据库迁移与回滚说明、服务端对象/数据范围授权、幂等与并发控制、审计与脱敏日志、失败补偿或明确的失败关闭策略、单元/接口/MySQL 回归证据，以及对应需求、架构、流程和 OpenAPI 文档。

受控跳转执行进入生产实现前，必须完成以下门禁：审批 Flowable 实例已结束且结论为通过；申请、审批、目标节点和实例版本均一致；目标节点位于已发布的纠偏白名单；硬审批/会签/授权节点不可跨越；当前任务处置、候选人重算、SLA/通知影响预演和事务回滚方案均通过。任一门禁失败时只保留申请与审计，不改变工单或流程实例。

## 7. 当前开发上下文与迭代计划

| 迭代 | 目标 | 关键交付与退出条件 |
| --- | --- | --- |
| A：受控跳转闭环 | 高风险纠偏可审计、可回滚 | 执行结果投影、通知重算、受控管理入口、普通处理人越权回归和真实 MySQL 三身份 HTTP 闭环已完成；待补数据库故障回滚演练及生产环境容量/可用性门禁，未满足门禁不向普通用户开放 |
| B：流程引擎产品化 | 后续审批/流程变更不靠改代码 | 审批待办、只读流程定义版本登记、IAM 用户—平台角色只读投影、审批策略快照及追加式审批决策记录已落地；申请以冻结的 Flowable 具体定义 ID/版本和具体 IAM 审批人启动，历史无定义 ID/人员集合记录禁止续审。并行多实例 `ANY_ONE`/`ALL_OF` 已由 BPMN 实现，模式只由部署受控策略决定。分派/转办/协办/交接已拒绝未启用或无活动支持角色的候选人。待补代理、超时升级、比例会签、流程迁移与真实 MySQL 历史兼容；会签/代理候选人不得使用浏览器提交的人员或角色 |
| C：身份与范围 | IAM、SSO 与组织数据权限生产边界 | IAM 用户/组织只读投影与平台后台授权已分离：所有 IAM 用户默认普通提单人；后台人员按 IAM ID 受控绑定角色与数据范围，具备乐观锁、审计、禁止自我提权和最后管理员保护。可选 OIDC 成功回调已将受验证主体映射到本地授权；待以实际 IAM 参数完成联调、补充 SAML 适配、范围下推、候选人和值班规则、停用与调岗处置 |
| D：运营与集成 | 服务台可运营能力 | SLA/OLA 配置、知识审核/检索、运营报表、WPS IM、CMDB/告警/日志/APM 适配器 |
| E：生产就绪 | 验证 7×24、1,000 并发与等保二级 | 分页/索引、压测、HA、备份恢复、安全扫描、SBOM、信创 POC 与演练 |

当前基础：Vue 3、Spring Boot 单体、MySQL/Flyway、Flowable、服务目录、结构化建单、固定队列、IAM 只读投影、身份快照、SLA、关联工单、通知 Outbox 与受控跳转审批/预演/执行骨架已存在。本地 `mysql,local-dev` 仅用于功能验证，不是生产设计。每个迭代可连续开发多个相互依赖的小项，但迭代收口必须集中完成构建、接口、MySQL、权限回归以及需求、架构、流程、OpenAPI 文档同步。
