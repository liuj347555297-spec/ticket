# 表单配置与发布治理

## 范围

服务目录的业务表单采用版本化配置。管理员配置草稿，经双人复核发布后，建单页和服务端校验同时使用该已发布版本；工单保存提交时的表单版本，不受后续配置变更影响。

## 最新布局修订：恢复参考截图的完整工作区

用户反馈三步向导隐藏内容且控件样式异常。本次修订替代下文历史三步设计：桌面采用约 3:1 主表单/右侧辅助区，主题在页签上方；基础信息页签内完整显示申请人、服务选择、动态字段、富文本、附件；关联工单和流程图页签重新可访问。右侧时效、状态、知识和标签持续可见，新单无服务器事实时仅显示待生成状态。

保留提交会话和附件部分成功回执；将步骤确认改为可取消的 Element Plus 确认弹窗，打开前校验并切回基础信息聚焦首错。按 Enter 不触发创建；只有明确点击提交并确认才发送。弹窗不销毁编辑器和已选附件。提交中锁定表单；结果不明仍仅允许同幂等键同请求重试。页面使用独立布局类，原生表单 input 规则排除组件内部输入，避免双边框和选中值遮挡；移动端改为单列，不影响桌面完整信息架构。

验收：真实本地服务读取目录后，主题/申请人/动态字段/富文本/附件/标签同屏可见；服务和枚举选中值清晰，无双边框；流程图页签可加载；取消提交确认后文本与附件仍在；模拟接口核对未确认时零创建、确认后防重及回执继续生效。对照桌面截图及 375px 单列布局，执行生产构建和提交会话回归。

## 字段边界

### 工单处理页截图对齐（2026-09-03 用户确认）

本次明确调整已存在工单的处理/详情页，与新建页分开。桌面左侧约 3/4 为单页处理工作区：基础信息、处理意见、解决信息连续展示；关联、审批、流程/历史、协作记录可通过页签访问，不删除原有能力。右侧固定归集服务端 SLA、状态/主办人和真实知识库搜索。底部显示服务端 `availableActions` 返回的动作及禁用理由；不复制截图中当前身份不可执行的按钮，不直接改状态。

处理意见复用现有 INTERNAL_COMMENT，正文以纯文本提交（上限 2000 字符）；解决类别与解决说明拼接为现有 RESOLVE 的 reason（上限 1000 字符）。编辑器支持本页排版，但必须提示当前接口保存纯文本，不提交未受支持的富文本/图片、实际解决时间等字段。对后端保存 reason 的审批/交接/协办/受控跳转动作，补充说明须纳入实际 reason，不能静默丢弃。CLAIM、TRANSFER、RESUME、CLASSIFY、REQUEST_USER_FEEDBACK 当前不保存 reason，确认框不提供伪保存理由控件，动作成功也不清理未提交意见，须单独保存为内部记录。真实只读数据（类型、优先级、人员、SLA）采用只读栏；后端未提供编辑接口的字段不可伪装成可保存控件。

底部动作先读取主表单对应草稿，再进入既有操作确认：取消确认/接口失败保留内存草稿，成功且刷新确认后清理对应内容；演示与无权限状态禁写。路由切单、身份变化或卸载时清理草稿、关闭未完成确认并使旧响应失效；在途动作不能并发重复提交，理由/正文不能进入本地存储或 URL。

右侧知识区按现有授权知识 API 获取发布条目，明确加载、失败、空结果，可输入关键词并打开文章；不得自动上传当前工单正文、伪造命中结果或将知识写入工单。知识查看在新标签打开，避免丢失未保存处理意见。

验收包括截图对齐、只读/处理人两种权限、处理正文和解决依据请求载荷、取消不丢字、长度拒绝、失败保留、切单隔离、移动端无溢出及新建页回归。审批成功提示区分“已完成动作”和“已发起审批”。

| 分类 | 示例 | 规则 |
| --- | --- | --- |
| 系统字段 | 工单编号、状态、流程、处理人、附件、审计时间 | 不可配置、不可由浏览器提交覆盖 |
| IAM 身份字段 | 申请人、申请组织、IAM 用户 ID | 只读投影；提交时写入身份快照 |
| 核心工单字段 | 主题、问题说明、标签 | 由平台安全规则控制；说明富文本必须经服务端清洗 |
| 目录业务字段 | 应用系统、业务分类、错误码、影响范围、期望时间 | 随服务目录的已发布表单版本配置 |

可配置业务字段包括文本、长文本、单选、多选、日期时间、布尔、标签、配置项引用和受控富文本。受控富文本只允许映射核心 `description` 字段，复用平台的 HTML 白名单、图片扫描和对象授权链路；不得存入任意动态结构化字段。

## 发布状态

```text
草稿(DRAFT) → 发布申请(PENDING_REVIEW) → 已发布(PUBLISHED) → 停用(RETIRED)
                                  ↘ 驳回/退回草稿(REJECTED)
```

1. 草稿可维护字段、顺序、默认值、字典、帮助文字、显示条件、必填条件和标签策略。
2. 发布申请会校验字段编码、系统字段黑名单、字典有效性、条件依赖顺序、富文本限制和组织数据范围。
3. 申请人与审批人必须不同，满足双人复核；审批、发布、停用和回滚均产生审计事件。
4. 停用后的回滚不会重写历史，而是从不可变的已发布快照创建新的草稿，再走发布流程。

## 运行时契约

- 请求人只能读取已发布表单；同一目录存在新配置时，新配置优先，旧目录模型仅作兼容兜底。
- 建单请求的 `serviceCatalogFormVersion` 必须等于当前已发布版本；旧页面或并发修改导致的旧版本提交会被拒绝。
- 服务端负责字段类型、字典选项、默认值、可见/必填条件和标签策略校验，前端只负责呈现和辅助校验。
- 工单持久化 `serviceCatalogFormVersion`，响应与审计记录均带上该版本，保证历史可追溯。

## 请求人页面渲染规则

- 请求人接口只下发当前已发布版本的字段元数据：字段类型、默认值、帮助文字、字典、显示条件与必填条件；不下发路由、SLA、审批候选人或规则表达式。
- 页面按 `displayOrder` 渲染。`visibleWhen` 与 `requiredWhen` 只支持 `EQUALS`、`NOT_EQUALS`、`IN`、`NOT_IN`、`HAS_VALUE`、`NO_VALUE` 的受控比较，所有条件同时满足才生效；隐藏字段不提交。
- 默认值先在页面展示，服务端仍会对遗漏的受控默认值重新计算、校验并持久化。浏览器提交的字段定义、可见性或默认值均不被信任。
- `LONG_TEXT`、`DATETIME`、`BOOLEAN`、`SINGLE_SELECT`、`MULTI_SELECT` 由标准 Element Plus 表单控件承载；`RICH_TEXT` 始终复用唯一的核心说明编辑器，`TAGS` 始终复用受控标签区，二者禁止条件隐藏，避免前后端语义不一致。
- `CI_REFERENCE` 录入的 CI 编码会合并为工单的配置项关联；创建前由服务端确认其属于 CMDB 只读投影，拒绝未知、非 CMDB 或超过数量上限的引用。

## 请求人三步建单交互规范

请求人页面固定为“选择服务、填写信息、确认提交”三个主步骤。服务目录/系统/模块联动在第一步完成；第二步按基本信息、影响与紧急程度、说明和附件分组；第三步只读汇总服务、组织、关键字段和附件状态。复杂表单通过分组与条件显示解决，不新增面向用户的后台配置步骤。

- 安全草稿在可持久化字段有效变化后 2 秒防抖写入当前标签页 `sessionStorage`，键包含组织、IAM 用户、目录和表单版本，最长 24 小时过期。仅保存系统/目录及字段元数据明确标记为非敏感的布尔、枚举和日期选项；主题、自由正文、自定义标签、附件及文件名、凭据、Blob/Base64、候选人或授权数据不得持久化，登出/换身份/主动删除时清理。
- 服务端草稿为后续能力。接口上线前必须写明“仅当前浏览器”；上线后用版本和更新时间解决本地/服务端冲突，恢复前提示用户，不静默覆盖。
- 恢复提示展示目录、保存时间和版本，提供恢复/放弃。版本不同时只映射兼容字段并列出未恢复项；恢复后仍执行当前版本全部条件和服务端校验。
- 条件字段就近解释为何出现；隐藏时不提交、不显示隐藏错误。校验在 blur/change 或前进/提交后出现，输入中至少 300ms 防抖，不弹窗/抢焦点。
- 提交错误页首汇总并关联字段，带请求关联 ID；首错 100ms 内滚动聚焦。内容始终保留，除非用户明确放弃。
- 主单创建和附件处理分离；主单成功后附件失败进入原单恢复，不重新创建主单。离开提示仅针对未保存变化、待上传附件或待处理恢复草稿。
- 键盘焦点、错误 `aria-describedby`/实时区域和移动端单列顺序必须与视觉一致；最终提交防重复，中间控件 Enter 不误提交。

## 工作台默认视图与真实数据状态

默认视图由服务端角色/范围能力决定：提单人“我发起的”、一线“我的待办/团队未领取”、二线“专业待办”、主管“队列风险”、服务经理“运营”、审计员“只读审计”、平台管理员“配置治理”。本地偏好只能在授权视图中选择，撤权后失效。

工作台组件必须实现 `LOADING`、`READY`、`EMPTY`、`ERROR`、`STALE`、`PARTIAL` 六种呈现状态。`EMPTY` 只对应成功零结果；`STALE` 显示 `asOf` 和延迟；`ERROR` 显示请求 ID/重试；`PARTIAL` 逐卡片隔离且不产生伪合计。旧值若保留必须标记时间，禁止硬编码健康、重大事件、班次、推荐内容或用零替代不可用。

## 管理权限

- `ROLE_SERVICE_MANAGER`、`ROLE_PLATFORM_ADMIN`：读取与写入配置。
- `ROLE_AUDITOR`：只读查看。
- 非平台管理员只能管理拥有 `DATA_SCOPE_ORGANIZATION:<组织ID>` 的适用组织范围；无组织范围的配置不向其开放。
- 所有写操作携带幂等键和版本号；更新使用乐观锁，冲突必须重新加载后处理。

## 团队队列配置与发布治理

团队队列与表单一样属于受控配置，但队列版本独立于表单版本。队列至少保存稳定编码、名称、`owningOrganizationId`、`serviceCatalogItemIds`、可选系统/CI 范围、支持角色、成员、主管、分派模式、共享领取开关、容量、升级链、有效期、状态和版本。队列范围按组织与服务目录取交集，系统/CI 只允许进一步收窄。

### 队列成员和权限

- 队列成员引用 IAM 用户 ID，并固化成员类型、有效期、添加人和队列版本；浏览器不能提交角色、组织或数据范围快照。
- 管理队列要求 `ROLE_SERVICE_MANAGER` 或 `ROLE_PLATFORM_ADMIN`，并命中 `DATA_SCOPE_ORGANIZATION:<owningOrganizationId>`；读取主管工作台还必须具有目标队列管理关系。角色或范围任一缺失时关闭式拒绝。
- 普通成员只获得活动节点候选和共享领取资格；主管获得受控分派、回收、升级、容量和成员管理能力。主管身份不自动授予其他队列、其他组织或超出服务目录范围的业务数据。
- 激活队列必须至少有一个已发布目录、一个活动成员和一个活动主管。空组织、空目录、空成员、空主管、目录越权或 IAM 不可验证时保持草稿，不能出现在路由、队列目录或工作台中。

### 共享领取与停用

- 共享领取要求已发布节点策略和活动队列均启用；领取时重新校验成员有效期、候选角色、对象范围、容量、工单版本和唯一活动主办约束。
- 停用队列必须提交替代队列、原因和影响预演。未领取任务可原子迁移；已有主办的在办任务保留责任与 SLA，并由主管逐单交接。存在无替代范围、越权目录或不可迁移任务时禁止停用。
- 范围缩小、主管移除、共享领取关闭和容量下降若影响进行中任务，必须使用与停用相同的预演和生效边界；不得覆盖历史队列、成员和路由快照。
- 队列配置、成员变更、共享领取、停用和迁移均写入追加式审计事件；更新使用乐观锁，重复提交使用幂等键。

旧队列若缺少可信 `owningOrganizationId`、非空 `serviceCatalogItemIds`、活动成员或主管，统一进入 `MIGRATION_PENDING`。该状态不接收新路由、不开放共享领取、不进入主管工作台；既有在办工单保持原队列、主办与 SLA 快照，仅由当前仍具对象权限的主体继续处理。迁移只能依据受控路由/目录关系和 IAM 稳定 ID 补齐，保存映射依据、执行人、复核人和结果，双人复核后发布新队列版本，不改写历史责任证据。

### 写操作幂等契约

- 队列创建、更新、成员/主管/范围变更、激活、停用计划创建、审批、执行、重试和取消全部要求 `Idempotency-Key`。服务端以主体、方法、规范化资源/动作和键定位记录，并保存规范化请求指纹与原响应引用。
- 同键同指纹重放返回首次等价结果，不重复业务副作用；同键异指纹返回 409。原因、期望版本、成员/范围、替代队列、计划/动作都参与指纹。
- 幂等键不替代 CSRF、角色、`DATA_SCOPE`、状态机和乐观锁。执行中或状态未知时，客户端先查询原资源/计划；不能换键盲重试。
- 异步执行以计划级保留和计划项级自然键双重去重。每个成功项保存迁移/交接/通知/审计结果引用，后续重试跳过；失败项明确可重试性和安全原因码。

`IN_PROGRESS` 幂等记录必须支持状态查询，至少包含首次接收时间、最近心跳、租约到期时间、资源/计划引用和安全重试建议。客户端在超时或执行中只使用原键重放/查询，不得换键；管理 UI/SDK 不提供“生成新键强制重试”能力。

执行租约包含版本、节点标识摘要、租约令牌摘要、`leaseExpiresAt` 和心跳。租约未过期时其他节点不能执行业务；过期后以数据库 CAS 原子接管，旧令牌立即失效。接管前先按计划项自然键、业务结果引用和审计关联对账：结果已存在时优先补记 `COMPLETED` 并返回原响应，结果不存在才继续未完成项。

业务事务必须保存幂等记录/操作自然键的唯一关联，以覆盖“业务提交成功、幂等完成标记前崩溃”的窗口。无法确认既有结果是否属于该主体、资源和指纹时关闭式进入人工处置，不重新执行业务。

请求指纹由服务端规范化请求后以受管密钥计算 HMAC，客户端对此透明。记录保存密钥版本，比较使用常量时间；轮换后旧记录在保留期内继续用固化版本验证，新记录使用当前版本。密钥版本不可用时先对账并阻断，不允许降级普通哈希、接受客户端指纹或跳过验证。

### 历史幂等记录升级

缺少新 HMAC 指纹、`keyVersion`、可信租约或业务结果唯一关联的历史记录不进入自动重放执行器。升级任务不得根据旧正文、时间接近或当前密钥猜测/补算指纹，只能依据业务自然键、资源版本和不可修改审计证据进行对账，并将记录归为：

- `LEGACY_RESULT_ONLY`：已确认既有业务结果，只返回安全结果引用，永不重新执行。
- `RECONCILIATION_REQUIRED`：结果是否提交无法确认，返回人工处置建议/引用；保持原 key，禁止自动重试。
- `FAILED_FINAL`：确认不可安全恢复，返回脱敏失败摘要和受控的新业务指引；客户端不能自动生成新 key。

状态查询和原写接口重放均返回同一历史状态语义。管理 UI/SDK 不提供强制重放或换 key 功能；只有用户明确确认新的业务意图时，才能在独立新请求中生成新 key。人工对账要求队列管理角色、组织 `DATA_SCOPE` 和复核，且只追加证据/结论/审计，不改写原记录、原业务事件或伪造 HMAC。

### 停用预演计划

停用先创建版本化计划，计划冻结源队列与版本、替代队列、原因、申请人、组织/目录范围、查询快照、清单哈希、SLA/通知影响，以及每个未领取迁移项和在办交接项的稳定 ID、工单/任务期望版本。计划完成预演后才能提交非申请人审批，审批只对该计划版本有效。

执行计划时先原子进入 `EXECUTING`。未领取任务逐项原子迁移；在办任务仅生成交接清单并等待确认，不能直接改主办或 SLA。计划支持 `PARTIALLY_COMPLETED` 和可恢复重试：重试只处理未执行/可重试失败项，成功项不重复。全部迁移成功、全部交接项有效且无阻断后才停用队列；否则保留过渡状态供主管处置。

计划查询响应必须包含状态、版本、审批摘要、影响数量、阻断摘要和可分页逐项结果（项 ID、类别、状态、尝试次数、结果码、是否可重试、结果引用），同时遵守队列组织范围和防枚举规则。管理 UI 最终必须展示这些信息并禁用重复执行；在 UI 交付前，本批可先实现 API，但生产环境不开放直接停用入口。

### 主管工作台

主管工作台仅汇总当前用户明确管理且数据范围命中的队列，至少展示未领取、处理中、临近违约、已违约、超容量、长时间无更新、待交接和成员负荷。数量、列表、成员负荷与导出使用同一授权谓词和查询快照；空 `DATA_SCOPE` 返回空工作台并隐藏全部管理动作，不回退为集团全量或仅按角色展示。

## 知识归属与发布治理

知识文档必须固化 `owningOrganizationId` 和非空 `serviceCatalogItemIds`。文档版本保存其归属组织、服务目录集合、来源类型、来源工单、创建人、审核人和发布时间快照；已发布版本不可原地修改归属，任何变更均创建新草稿并重新审核。

### 创建与导入

- 从已解决/关闭工单创建知识草稿时，服务端从工单冻结快照继承 `owningOrganizationId` 与 `serviceCatalogItemIds`。浏览器无权覆盖；源单缺少任一快照、主体无源单读取权或无目标组织知识管理范围时不创建草稿。
- 受控导入的 `owningOrganizationId` 只能取服务端当前 IAM 主组织。浏览器只能提交服务端返回的目录候选，服务端逐个校验目录已发布、位于当前组织管理范围且集合非空；请求体组织 ID、文件路径、标题、标签和文件内容均不能决定归属。
- 当前 IAM 组织为空、组织投影不可验证、目录为空或 `DATA_SCOPE` 不命中时关闭式失败，不使用平台组织、默认组织或全局目录兜底。

### 读取与管理谓词

- 普通用户只能读取 `PUBLISHED` 状态、`owningOrganizationId` 等于当前 IAM 组织且目录范围相交的知识。组织 A 的发布不使组织 B 自动可见；跨组织共享不属于本批能力。
- 上传版本、提交审核、审核、发布、归档、复审、从工单生成草稿和导入必须具有 `ROLE_SERVICE_MANAGER` 或 `ROLE_PLATFORM_ADMIN`，并命中 `DATA_SCOPE_ORGANIZATION:<owningOrganizationId>`；平台管理员同样遵守。`ROLE_AUDITOR` 只能在命中范围内读取审计元数据，不能执行管理动作。
- 知识列表、详情、版本历史、审核队列、复审候选、正文预览、附件下载、反馈提交和反馈汇总复用同一组织、目录和状态授权谓词。任一入口不得单独放宽，也不得用数量、空页或错误差异泄露其他组织记录。
- 审核任务创建时固化文档版本、组织、目录和候选审核人。审核人处理时再次校验角色、数据范围、非自审和版本；组织/目录变化必须使旧任务失效，而不是沿用旧权限发布。

### 旧知识迁移

1. 迁移前盘点所有缺少 `owningOrganizationId` 或 `serviceCatalogItemIds` 的知识和版本，并统一标记为 `MIGRATION_PENDING`；该状态只允许获授权审计主体查看元数据。
2. 映射只能来自可信源工单快照、既有受控目录关系或经双人复核的组织/目录映射表。禁止按作者、文件夹、标题、标签或当前执行人猜测归属。
3. 迁移预演输出待映射、冲突、失效目录和无映射清单；只有组织、非空目录、目录状态和范围全部通过的记录可执行。
4. 执行保存旧 ID、目标组织、目录集合、映射依据、执行人、复核人、时间、结果和校验哈希。歧义或空映射继续保持 `MIGRATION_PENDING`，不得自动成为全局知识。
5. 迁移完成后抽样验证普通列表、审核队列、版本、预览、附件和反馈均使用统一谓词；发现越权立即停止批次并回滚该批新映射，不改写旧版本证据。

## 附件扫描与知识发布门禁

附件/知识源文件的统一状态为 `QUARANTINED`、`CLEAN`、`REJECTED`、`SCAN_FAILED`。上传完成固定进入 `QUARANTINED`；只有受管扫描器对服务端计算的内容哈希给出可信通过结果，且类型/大小策略同时满足时才能转 `CLEAN`。扫描器不可用、超时或内部错误必须转 `SCAN_FAILED`，不能将“未发现问题”或“扫描未完成”解释为通过。

- 所有非 `CLEAN` 文件禁止下载、内联预览、正文替换、解析、索引、案例匹配和知识发布。知识审核/发布在执行时逐附件重新读取状态；不能只依赖提交审核时的快照。
- `REJECTED` 为原内容最终拒绝，不允许重试原文件；重新上传产生新的隔离附件。`SCAN_FAILED` 可按服务端策略重试，但需要对象权限、稳定附件 ID、幂等键、失败状态条件、内容哈希一致、次数/退避限制和扫描器健康。
- 每次尝试保存序号、触发人、时间、扫描器配置版本、脱敏结果和审计。并发重试通过自然键/状态锁仅保留一个有效任务；已存在结果优先返回，不重复扫描任务或业务审计。
- 最大次数耗尽、文件缺失/哈希变化、扫描回执来源不可验证或状态并发变化时关闭式失败并进入人工处置。人工人员不能直接把状态改为 `CLEAN`，只能修复扫描能力后重新走受控扫描。
- 前端只展示服务端状态和能力。四种状态分别提供“待扫描、可使用、已拒绝、扫描失败”提示；非 CLEAN 隐藏下载/预览，只有 `SCAN_FAILED` 且服务端允许时显示重试。工单已创建但附件失败时保留原工单恢复路径，不建议重复建单。

## 2026-09-03 提交回执及工作台交互设计

创建操作使用页面内存中的提交会话：首次确认冻结 JSON 请求和幂等键；在途点击复用同一 Promise；结果不明的重试复用请求和键；收到主单编号即转入只读回执，禁止再次调用 create。明确的 4xx 拒绝（不含超时/请求在途冲突）才释放原请求以便修改。刷新不自动重放，不持久化业务正文，用户需先到工单中心核对结果。

附件沿用原上传接口，逐文件记录客户端观察到的状态，仅 CLEAN 图片可写入正文。网络失败一律显示“结果待核对”，不推断服务端未接收，不自动重传；正文更新失败不回滚主单，不重新上传已成功文件。用户从回执进入原单详情后查看已有附件并手工补齐。

工作台保存各固定队列的独立结果/加载/错误状态，活动队列仅切换展示，不把 MY_TODO 列表当作 MY_REQUESTED。仅失败项重试时保留成功结果，防止重复请求竞争覆盖，卸载/身份变化使旧请求失效。静态分类入口不得保留无动作按钮或声称来自未调用的 API。

验收：可重复执行的提交会话测试覆盖并发、成功缓存、超时后同键同内容重试；浏览器模拟接口覆盖前两步回车零次 create、单文件失败仅一张主单、移动错误可见、队列切换不同结果、部分重试不请求成功分区。本批不修改服务端流程定义及数据库结构。
