# 系统配置入口整合：需求、设计与实施

## 1. 本次需求

服务配置、流程表单设计和新建系统归入同一配置入口，操作顺序为：新建/选择系统 → 配置系统下工单服务 → 配置该服务的表单和流程。流程表单不再作为独立导航菜单或独立全局页面。

沿用现有系统、服务和设计数据，不删除旧设计，不将设计草稿当作已发布运行流程。本次为管理入口与设计归属整合，不放开尚未完成的 BPMN 运行发布。

## 2. 交互设计

- 唯一菜单“系统服务配置”，路由 `/service-config`。无系统时显示建系统引导；已有系统先选择，可在同页新建系统。系统必须保存成功后才可配置其下的设计。
- 选中系统后集中展示该系统工单服务，提供服务配置入口；新工单设计可先归属于系统，待具体服务目录就绪后再关联该服务。
- 流程/表单编辑器作为系统配置页内嵌工作区，从当前系统或具体服务进入，显示系统/服务上下文和返回操作。编辑器内部的流程、表单、校验切换只是当前设计的工具，不是独立导航页。
- 系统和组织在设计器内只读继承，不能在编辑中任意切换归属。切换系统/服务、返回、进入其他配置区域必须检查未保存设计；忙碌时不可离开，不确定创建保留原幂等请求。
- 旧 `/design-studio` 地址兼容跳转到系统服务配置，提示先选系统。旧未归属设计只能在相同组织的系统内明确选择并归入，不自动按名称猜测归属。

## 3. 数据与服务端边界

设计包及摘要增加可空 `systemCode`、`serviceCatalogItemId`。历史 JSON 缺字段时按未归属旧设计读取，组织范围仍沿用既有服务端权限。创建或更新指定归属时，服务端验证真实系统、组织一致、操作人范围，以及可选服务与该系统/模块已有启用映射的关系；不能只信前端过滤。

同组织未归属旧设计可通过正常版本锁保存明确归入系统。已经归属系统的设计不得搬到其他系统，已经绑定具体服务的设计不得悄悄换绑服务；保留冻结表单不可变与 DRAFT_ONLY。设计包仍存在原 JSON 持久化中，不迁移或修改发布数据。

## 4. 实施顺序与分工

1. 本文先落需求与边界。
2. 后端增加设计归属字段、校验、旧 JSON 兼容与回归测试；保持公开工作流预览不变。
3. 前端将设计器参数化/内嵌，按系统与服务过滤已归属设计，同组织旧设计显式归入；增加父页面离开保护接口。
4. 父页面整合菜单、建系统后继续配置入口、服务卡片到设计器，以及旧路由重定向。
5. 构建、权限/归属测试与浏览器验证。验收不发布真实服务，不部署自由 BPMN，不删除旧数据。

## 5. 验收

侧栏只有系统服务配置，没有独立流程表单菜单；必须先有系统才进入设计。保存新系统后停留同页并能继续配置；已有服务可在当前系统内查看表单并进入设计，系统/服务上下文始终可见。不同系统设计不混列，旧设计有明确归入入口，未保存切换可取消。刷新重开可恢复真实归属，跨组织和伪造映射服务端拒绝。发布运行仍明确未开放。

## 6. 实施与验收记录（2026-09-04）

已完成统一入口。侧栏只保留“系统服务配置”；`/design-studio` 保留兼容重定向并返回 `/service-config`，不再呈现独立设计页。选中系统后可以新建系统级工单设计，或从具体服务卡片进入“配置表单与流程”。新系统保存后在当前页显示下一步入口；服务库与公告收进“更多工具”。

设计包已增加 `systemCode` 和可选 `serviceCatalogItemId`，服务端验证真实系统、组织和启用映射。旧 JSON 缺少新字段仍正常读取，本地原“多表单审批设计验收”实测保持未归属状态，没有被自动改写；页面通过“归入已有设计”要求管理员明确确认并保存。归属一旦保存不能清除或换到其他系统/服务，系统级设计可后续关联当前系统内真实服务。

内嵌设计器继续保留流程、表单、发布检查三个编辑工具，但它们只属于当前系统配置工作区，不是全局页签或侧栏入口。系统和组织只读继承；服务级读取旧表单只读取当前真实服务，seed 服务走公开已发布表单，managed 服务走受控后台定义。

并发边界已补齐：所有父级切换委托内嵌设计器判断未保存内容；忙碌时禁止切换，用户可取消放弃。相同主体权限刷新会保留脏数据、运行中的操作和未确认创建请求；原请求体与幂等键不会重建。跨主体时不允许新身份重试原未确认创建，并给出核对提示。设计列表使用独立请求序号，旧刷新结果不能覆盖保存后的新列表。
