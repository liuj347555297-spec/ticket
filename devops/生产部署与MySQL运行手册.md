# 生产部署与 MySQL 运行手册

适用范围：内网 Linux 环境的 ServiceHub 后端。部署形态为 Spring Boot 单体、MySQL 8、受管 IAM/OIDC、反向代理和受控附件卷。本文不包含真实地址、账号、密码、令牌或证书私钥。

## 1. 运行边界

| 项目 | 生产要求 |
|---|---|
| 激活 profile | `mysql,prod`；严禁启用 `local-dev`。 |
| 数据库账号 | 运行账号仅业务 DML；Flyway 账号仅目标库 DDL/DML；备份/恢复账号由 DBA 单独管理。 |
| 密钥 | 仅由密钥管理系统、编排平台 secret 或权限为 `0600` 的容器挂载文件注入；不进入镜像、compose、环境文件、日志或工单。 |
| 附件 | 挂载到非 Web 根目录的持久卷；生产必须启用真实受管扫描器，扫描隔离/清理策略按附件安全方案执行。 |
| 扫描网络 | 应用只可访问固定 ClamAV Unix socket、sidecar 或内网允许地址；扫描器不得访问互联网、对象存储管理面或非必要内网。 |
| 网络 | 后端仅由反向代理或服务网格访问；数据库不向应用网段以外开放。 |
| 身份 | IAM/OIDC 启用前不得将系统作为生产入口；不能以本地账户或开发身份替代。 |

## 2. 配置清单

从 [`devops/.env.production.example`](.env.production.example) 取得变量清单，实际值交由部署平台注入。生产 profile 会要求所有数据库、迁移、附件目录和前端来源变量存在；缺失会启动失败。

必须区分以下身份：

- `SERVICEHUB_DB_*`：应用运行账号，无 `CREATE`、`ALTER`、`DROP`、`GRANT`。
- `SERVICEHUB_FLYWAY_DB_*`：已审批的迁移账号，只限 ServiceHub 目标库。
- MySQL 客户端 defaults 文件：备份/恢复专用账号，仓库外保存，权限 `0600`。

`SERVICEHUB_SECURITY_ALLOWED_ORIGINS` 只能填写受管 HTTPS 门户来源（逗号分隔），不能使用 `*`。应用的执行权限、审批候选人和 IAM 投影继续由服务端控制，反向代理不替代对象级授权。

生产扫描器配置必须由部署平台冻结并注入，不接受业务数据库、管理员页面或附件元数据提供的主机、端口、协议、DNS、代理或命令。扫描器服务身份/凭据与 IAM、对象存储、消息通道和幂等 HMAC 密钥分域，禁止复用、相互派生或把扫描器/签名版本填作 HMAC `keyVersion`。环境清单与配置展开输出只能显示“已配置/未配置”和脱敏版本，不打印端点、凭据、证书路径或密钥材料。

## 3. 容器发布

在仓库根目录构建不可变镜像：

```bash
docker build -f backend/Dockerfile -t registry.internal.example/servicehub/backend:<immutable-tag> .
```

部署机使用经密钥平台渲染的私有环境文件，先进行配置展开校验，再启动：

```bash
docker compose --env-file /run/servicehub/production.env -f devops/docker-compose.production.yml config --quiet
docker compose --env-file /run/servicehub/production.env -f devops/docker-compose.production.yml up -d
```

compose 模板默认只绑定 loopback；由批准的反向代理提供 TLS、访问日志、请求体限制和 IAM 登录跳转。容器使用非 root 用户、只读根文件系统、无 Linux capabilities，并只允许附件/临时目录写入。

### 3.1 附件扫描器启动与运行门禁

生产发布必须证明应用选用真实受管扫描器，且不存在 noop、固定通过、跳过扫描或扫描失败放行开关。启动探针至少验证配置完整、目标命中部署允许列表、出站网络策略生效、ClamAV 引擎健康和病毒库在批准的新鲜度窗口内；任一项失败时应用不得接入附件入口/扫描工作者流量，readiness 必须失败。运行中扫描器不可用不影响既有业务数据一致性，但所有新附件和未完成扫描保持隔离，禁止下载、预览、抽取、导入、发布或投递。

连接器必须设置连接、写入、读取和总时限，以及并发、队列、单文件/流量和最大响应字节/行数上限。只接受批准的 ClamAV 明确终态；拒绝连接、超时、中途断连、响应截断、畸形/超大响应、未知状态、引擎错误或签名库过期统一记录为 `SCAN_UNAVAILABLE`，不得映射为干净、不得“先放行后补扫”。恢复后的积压文件须重新取得明确干净结果，原不可用记录不能批量改为通过。

上线候选环境必须以隔离合成数据完成：EICAR 标准测试串命中、伪扩展名/伪 MIME、合成压缩炸弹/超层数、超时、拒绝连接、中途断连、截断/畸形/超大回执及病毒库过期。验收须证明全部异常关闭式失败、下游零读取/零解析/零发布/零投递、网络零越界，并扫描日志、审计、指标、错误和崩溃转储，确认不含样本、附件正文/文件名、原始回执、隔离路径、端点、凭据、HMAC/IAM/对象存储/消息密钥。

恶意命中、不可用、重扫、隔离及最终销毁/取证移交均写追加式审计，保留文件不可逆摘要、父对象脱敏引用、引擎/签名版本、规范化结果/原因码、耗时、服务身份/处置主体和关联 ID。解除隔离必须双人复核，且只能销毁、取证移交或受控重扫；禁止人工或 SQL 将记录直接改为 `SCAN_PASSED`。

## 4. 数据库与迁移发布门禁

1. DBA 在变更窗口前完成可恢复备份，并验证上一次恢复演练证据。
2. 用迁移账号对目标库执行一次候选版本启动；Flyway 会校验历史并前向执行 `V*` 迁移，禁止 `clean`，禁止修改既有版本文件。
3. 核对 `flyway_schema_history`、关键索引、字符集 `utf8mb4` 和应用账号的最小权限。
4. 再以运行账号发布应用，确认其不能执行 DDL，且建单、查询、审计写入正常。
5. 迁移失败立即停止发布；只通过经评审的前向修复或已演练的恢复处置，绝不编辑 Flyway 历史伪造成功。

Flowable 的 `ACT_*` 表不由本项目 Flyway 迁移管理。生产 profile 禁止其随普通应用滚动发布自动建表/升级。首次启用或 Flowable 升级必须由平台团队在隔离环境验证并走独立变更单（含定义版本、建表/升级 SQL、备份与回退）。在此变更完成前，生产应用应保持 `flowable.database-schema-update=false`。

### 4.1 V40/V41/V42 发布验证矩阵

V40、V41、V42 是一组需要独立证据的前向迁移；任一文件缺失、校验和与已发布不一致、对象清单未评审或无可恢复备份时均阻断发布。V42 的确切表/索引/约束清单以最终纳入仓库且通过评审的迁移文件为准，不得按文档猜测手工建对象。

| 路径 | 必须验证 | 阻断条件 |
| --- | --- | --- |
| 全新空库 | 以 MySQL 8 目标小版从 `V1` 顺序执行至 `V42`，导入受控 Flowable DDL，校验 Flyway 历史、表/列/索引/外键/CHECK、字符集、启动和最小业务写入 | 任一迁移跳号/失败，V40 队列/成员/路由对象缺失，V41 知识归属约束不生效，或 V42 审批清单不完整 |
| 官方基线新库 | 若使用已批准基线（例如 V34），先验证基线哈希/版本并仅对空库登记 baseline，再顺序执行后续至 V42；结果须与“V1→V42”空库结构对比 | 基线与迁移链结构不等价、baseline 被用于非空/已有历史库、或差异未解释 |
| 历史升级 | 恢复一份生产类似的 V39 脱敏副本，顺序执行 V40→V41→V42；校验旧工单/流程/知识/审计数量、外键完整性和应用兼容 | 历史数据被默认扩权/删除，旧知识未可信归属却仍业务可见，队列/任务快照错配，或 Flyway 历史不连续 |
| 恢复后升级 | 用与生产相同工具恢复升级前备份到隔离库，再迁移至 V42，运行完整性/权限/幂等/队列迁移和知识 fail-closed 抽验 | 备份不可恢复、恢复版本错误、迁移后对象/数据证据不完整 |

V40 重点验证团队/队列/成员/范围表、路由与任务队列字段、外键和路由快照；历史可空字段不得被视为全局队列。V41 重点验证知识文档/版本组织与目录归属；无可信归属的历史行必须为 `MIGRATION_PENDING` 且不可普通检索/预览/发布。V42 按最终脚本验证幂等和队列迁移计划/审批/逐任务证据的唯一键、状态约束、索引、外键与最小权限。

具备私有 MySQL 8 客户端配置的安全验证机可用以下方式执行空库链验证；脚本只允许创建/删除 `servicehub_migration_verify_*` 前缀的不存在 schema，且不在命令行接收密码：

```bash
SERVICEHUB_MYSQL_CLIENT_DEFAULTS_FILE=/run/servicehub/verify.cnf \
SERVICEHUB_MYSQL_VERIFY_DATABASE=servicehub_migration_verify_v42 \
SERVICEHUB_ALLOW_SCHEMA_CREATE_DROP=YES \
bash devops/verify-v42-mysql-migrations.sh
```

### 4.2 锁等待、DDL 时长与复制延迟门禁

候选库验证必须使用与生产接近的表行数、索引体积、MySQL 小版、副本拓扑和磁盘配额，对 V40/V41/V42 每条 DDL/DML 记录开始/结束、扫描/更新行数、元数据锁等待、实际执行时长、临时空间/日志增长和副本延迟峰值。变更单须在执行前固定逐项阈值与总窗口；无实测证据或任一项超阈值不得发布。

发布前检查长事务、未提交会话、元数据锁和副本状态；应用写入及后台任务必须按评审方案摘流/暂停。迁移会话使用独立、有界的锁等待/语句时间预算，禁止为了等待 DDL 修改全局超时。出现未预期元数据锁、长时间 DDL、临时空间不足、副本延迟超阈值或在线 DDL 算法/锁等级与预演不一致时立即停止；不得未经批准强制杀死业务会话或伪造 Flyway 成功。失败后只允许已评审的前向修复或整库恢复路径。

### 4.3 V43 幂等恢复与故障注入门禁

V43 须在 MySQL 8 空库 `V1→V43`、官方基线后前向至 V43、生产类似 V42 历史副本 `V42→V43` 以及升级前备份恢复后再升级四条路径验证。任一 V43 文件缺失/校验和变化，租约、`keyVersion`、尝试次数、结果引用/对账状态列或索引/约束与应用模型不一致，均阻断发布。V43 实物对象以最终已评审迁移脚本为准，不手工补列或改 Flyway 历史。

数据库演练除结构/约束外，必须构造过期/未过期 `IN_PROGRESS`、已成功但幂等未完成、幂等已完成但响应丢失、不确定结果和两节点竞争接管数据。执行 CAS 接管与结果对账，断言单一所有者、不重复业务/审计/outbox、不确定记录 fail-closed 且可告警。

应用故障注入在预留完成后、业务事务前，业务提交后/幂等完成前，幂等完成后/响应前分别强制终止节点，并注入 DB 断连、审计/outbox 失败、租约到期和时钟偏差。演练必须由隔离环境、合成数据和专用密钥完成，不使用生产幂等键、业务原文或生产 HMAC 密钥。

HMAC 部署门禁必须验证当前密钥至少32随机字节、每环境独立、仅受管注入、当前 `keyVersion` 唯一且前一版本只读验证。演练“预发布新验证能力→切换新签发→新旧并存验证→旧记录清窗→撤销旧密钥”；密钥、完整引用和 HMAC 中间值的日志/审计/指标/错误/崩溃转储扫描必须零命中。

### 4.4 V44 历史幂等分类与四路径验证

V44 必须验证：全新 MySQL 8 空库 `V1→V44`；官方基线后前向至 V44；恢复包含合成 V42 无 `keyVersion`/租约历史行的 V43 副本后执行 `V43→V44`；以及升级前备份恢复后再前向到 V44。V44 必须保留原状态/结果证据，把旧活动 `IN_PROGRESS`/不确定行安全分类为待对账/最终失败，不得填充当前 HMAC 版本或伪造强结果引用。

隔离副本在 V44 后必须执行以下等价核查，两个结果均必须为 `0`：

```sql
SELECT COUNT(*) AS null_key_version_count
FROM support_queue_command_idempotency
WHERE key_version IS NULL;

SELECT COUNT(*) AS active_legacy_in_progress_count
FROM support_queue_command_idempotency
WHERE status = 'IN_PROGRESS'
  AND (key_version IS NULL OR lease_owner IS NULL OR lease_expires_at IS NULL);
```

非零时禁止应用写流量和队列工作者启动，不得在启动脚本中现场 `UPDATE key_version=<current>`。如 V44 使用 `LEGACY_UNVERIFIED` 等专用分类值，须额外验证其不在 HMAC key ring、不可新签发/验签/自动重放，且只允许安全状态。对账抽样必须能关联业务、审计/outbox、操作/复核人、批次和最终判定，不查看或记录原请求正文。

发布后以原主体与无权主体分别查询幂等状态：原主体只看到操作/资源摘要、状态、尝试次数、租约到期、安全结果引用和原因码；无权主体不得枚举记录。响应、日志、审计和指标不得包含指纹、owner、`keyVersion`、密钥/引用或原始对账证据。

## 5. 健康检查与可观测性

`/actuator/health`、`/actuator/health/liveness` 与 `/actuator/health/readiness` 均受 `ACTUATOR_VIEW` 角色保护，不允许为了探针改为匿名访问。

- 容器 healthcheck 仅确认 JVM/HTTP 安全链可响应（预期 `401`），用于进程存活判断。
- 外部监控使用专用 IAM 服务身份访问 readiness；该检查包含数据库连通性。
- readiness 同时反映生产扫描器选择、ClamAV 引擎健康与签名库新鲜度；故障告警须区分恶意命中、不可用、超时/断连、响应异常、签名库过期、队列积压和隔离处置逾期。
- 反向代理对业务接口使用短超时、请求 ID 透传和访问日志脱敏；应用日志、审计事件和数据库慢日志统一接入现有内网日志平台。

发布后的最小验证：使用普通 IAM 用户建单；使用有范围的后台角色受理；使用监控身份读取 readiness；确认未经认证、跨对象、跨组织及无 CSRF 的请求都被拒绝。

## 6. 备份与恢复演练

[`backup-mysql.sh`](backup-mysql.sh) 使用事务一致性逻辑备份，并在写入后校验 gzip；[`restore-mysql.sh`](restore-mysql.sh) 仅允许恢复到明确命名的独立恢复库，且要求人工二次确认。二者均要求仓库外私有 MySQL client defaults 文件。

```bash
chmod 700 devops/backup-mysql.sh devops/restore-mysql.sh
SERVICEHUB_MYSQL_CLIENT_DEFAULTS_FILE=/run/servicehub/backup.cnf \
SERVICEHUB_DB_NAME=servicehub SERVICEHUB_BACKUP_DIR=/srv/backup/servicehub \
devops/backup-mysql.sh
```

至少按组织制度定期演练恢复：验证表、索引、Flyway 历史、抽样审计链和关键业务读写；演练目标必须是隔离库，禁止脚本覆盖生产库。备份留存、加密、异地副本及 RPO/RTO 由运维基线确定。

V40/V41/V42/V43 发布前必须生成一份可追溯的升级前备份，记录源库 Flyway 最高成功版本、GTID/binlog 位点（如适用）、备份哈希、大小、时间、加密/异地状态和恢复演练证据。隔离恢复后须分别验证“保持升级前版本可读写”与“恢复后再前向升级至当前目标版本”两条路径。备份除业务表外必须包含 Flyway 历史、Flowable 运行/历史表、审计、Outbox、队列快照和知识归属数据；附件/对象存储按同一恢复点策略独立校验。

## 7. 回退与停机

应用版本回退不等于数据库回退。若已执行不可兼容迁移，优先使用前向兼容补丁；只有在已验证备份、明确业务窗口及 DBA 批准下，才能恢复数据库。优雅停机最长由 `SERVICEHUB_SHUTDOWN_TIMEOUT` 控制，先从负载均衡摘流量，再停止实例并确认未完成的迁移/扫描/通知任务有可恢复策略。

V40、V41、V42 不提供未经演练的向下迁移。每个版本的变更单必须单独列出：旧应用读/写兼容性、可前向修复点、恢复前必须停止的写入/工作者、备份恢复预计数据损失窗口和恢复后重放/对账策略。迁移已成功但应用发布失败时，只在结构经证明向后兼容时回退应用；否则保持停写并执行前向修复或 DBA 批准的整库恢复。禁止手工删列/表/索引、修改 `flyway_schema_history` 或将部分完成的 V40/V41/V42 标记为成功。
